Palette metadata and protect masking

Palette metadata and protect masking

Properties1
tagsgenerator, conditioning

Jun 21, 202610 min read

In one sentence: two palette-aware preprocessing services — F2 palette metadata samples what colours the chosen filament stack can actually reach (an achievable-colour envelope), and F3 protect masking finds the photo’s subject (via rembg saliency, plus user brush/raster overrides) so that conditioning operators can soften their edits inside the subject and stay aggressive in the background.

These two services run in the generator.pipeline.runner F1 preprocessing slot, before the image is turned into a solve target and before the Staged backend does the actual layer solve. They are inputs that conditioning operators (C1, C2, B1, B3) consume — they do not themselves edit the image. Both are resolved once per solve and passed down through PreprocessingContext.

  • F2 = “what colours can this palette make?” → fed to operators that compress toward the gamut or remap tone.
  • F3 = “where is the subject?” → fed to operators as a per-pixel weight that blends an aggressive edit against a gentler one.

See also: Preprocessing chain, Conditioning operators, generator.preprocessing.palette_metadata, generator.preprocessing.protect_mask, generator.preprocessing.protect_blend.

How it wires into a solve

Both services are live and called from pipeline/runner.py inside run_pipeline, which the webapp/facade uses (facade.py:906 imports run_pipeline; run_pipeline later delegates the solve to run_staged_backend_path at pipeline/runner.py:843-846). Preprocessing happens in the if config.preprocessors: block (pipeline/runner.py:695) — that is, F2/F3 resolve and the chain runs before the staged backend ever sees the raster.

F2 — palette metadata (achievable-colour envelope)

Source: preprocessing/palette_metadata.py.

What it produces

resolve_palette_metadata returns a frozen PaletteMetadata with exactly four pinned fields plus a fingerprint (palette_metadata.py:140-152):

FieldShapeMeaning
achievable_black_oklab(3,) float32The darkest OKLab point the stack can reach (lowest L among sampled stacks) — palette_metadata.py:336
achievable_white_oklab(3,) float32The lightest reachable OKLab point (highest L) — palette_metadata.py:337
max_chroma_by_hue(n_bins,) float32Per-hue-bin maximum reachable chroma — palette_metadata.py:343
hue_degrees(n_bins,) float32Hue-bin centres these chroma caps belong to — palette_metadata.py:344
request_fingerprintstr32-hex digest of the producing request — palette_metadata.py:345

The black/white anchors are C1’s input; the per-hue chroma envelope is C2’s input (the module header at palette_metadata.py:11-14 calls these “the four pinned fields”, and the consuming operators confirm it — see below).

How the envelope is sampled

_candidate_oklab_points (palette_metadata.py:176) builds a cloud of OKLab points by composing transmission stacks within the print budget and projecting each to OKLab via compose + linear_to_oklab from lib/transmission.py (imported at palette_metadata.py:49; compose defined lib/transmission.py:146, linear_to_oklab lib/transmission.py:40). It is explicitly an envelope sampler, not a full polytope enumeration (palette_metadata.py:190-193).

The coverage strategy (palette_metadata.py:184-188):

  • White sandwich alone — white base + white cap, across three cap-thickness samples (d_wc_min, midpoint, d_wc_max; palette_metadata.py:196-200, palette_metadata.py:211-215).
  • Single-filament stacks — each palette colour at coarse thickness samples (palette_metadata.py:219-230).
  • Pairs (k=2) — every 2-combination, when k_max >= 2 (palette_metadata.py:233-250).
  • Triples (k=3) — every 3-combination, when k_max >= 3 (palette_metadata.py:253-273).

Thickness samples are coarse by design: at most _THICKNESS_SAMPLES_PER_LAYER = 4 per layer (palette_metadata.py:158), snapped to layer height by _layer_sample_thicknesses (palette_metadata.py:166-173). Each stack must fit the colour budget t_max - d_wb - d_wc (palette_metadata.py:208; pair/triple sums checked at palette_metadata.py:239 and palette_metadata.py:261). Corrections are applied to compose when use_corrections is set (palette_metadata.py:202-204).

From that point cloud:

  • black/white = argmin/argmax of L (palette_metadata.py:335-337).
  • chroma envelope = _chroma_envelope (palette_metadata.py:278) bins points by hue into _HUE_BINS_DEFAULT = 12 bins (30°-wide; palette_metadata.py:157) and takes the max chroma per bin, with empty bins set to 0 (palette_metadata.py:294-298).

If sampling somehow yields no points, the resolver falls back to the bare white-cap point for both anchors and an all-zero chroma envelope rather than failing (palette_metadata.py:317-333).

When it runs (opt-in) and how it is keyed

F2 is skipped unless some operator opts in. _chain_needs_palette_metadata (palette_metadata.py:349) returns True only if an operator declares "palette_metadata" in its required_context; otherwise resolve_palette_metadata_for_chain returns None and the chain sees context.palette_metadata = None (palette_metadata.py:375-378). The two opting-in operators are C1 (operators/c1_achievable_tonemap.py:229) and C2 (operators/c2_soft_gamut_compress.py:382) — both frozenset({"palette_metadata"}).

The request is the envelope-relevant slice of PipelineConfig, built by PaletteMetadataRequest.from_config (palette_metadata.py:90). It deliberately includes only fields that move the achievable envelope — palette (sorted, treated as an unordered set; palette_metadata.py:99), the white sandwich identities and thicknesses, t_max, k_max, layer_height, and corrections (palette_metadata.py:98-110). It deliberately excludes solver weights like de_threshold/gamut_mode/chroma_weight, grouping knobs, image resolution, and preprocessing params (palette_metadata.py:64-72). fingerprint() (palette_metadata.py:112) is a 32-char truncated SHA-256 over the rounded fields (palette_metadata.py:119-135); identical envelopes hash identically. This fingerprint is the palette-change invalidation key (header note palette_metadata.py:16-22).

How C1 and C2 consume it

OperatorUsesBehaviour on degenerate / missing
C1 achievable tonemapachievable_black_oklab / achievable_white_oklab L-endpoints to remap tone(anchor inputs per c1_achievable_tonemap.py:229 required_context)
C2 soft gamut compresshue_degrees + max_chroma_by_hue as the per-hue chroma ceilingraises if metadata is None (c2_soft_gamut_compress.py:441-444); returns an identity result if the envelope is empty / all-zero (c2_soft_gamut_compress.py:456-461)

C2 reads the two envelope arrays at c2_soft_gamut_compress.py:446-453, then interpolates a per-pixel chroma bound around the hue circle via _query_chroma_bound (c2_soft_gamut_compress.py:36) and soft-knee-compresses chroma toward it.

F3 — protect-subject masking

Sources: preprocessing/protect_mask.py (service + overrides), preprocessing/protect_mask_providers/rembg_u2net.py (saliency), preprocessing/protect_blend.py (weight + blend).

What it produces

ProtectMaskService.get returns a ProtectMaskResult (protect_mask.py:77): a final soft mask (HxW float32 in [0,1]), a confidence scalar, the provider name, a cache_hit flag, and debug_maps (protect_mask.py:396-402). The mask itself is just saliency-plus-overrides; it becomes an editing weight only after resolve_protect_blend_spec (below).

The provider: rembg / u2net saliency

The only registered provider is "rembg" (protect_mask_providers/__init__.py:18-21; unknown names raise KeyError at __init__.py:22). RembgU2NetProvider.predict (protect_mask_providers/rembg_u2net.py:21):

  • Lazily imports rembg and raises ProtectMaskUnavailableError with the install hint uv sync --group protect-mask-rembg if it is missing (rembg_u2net.py:22-28).
  • Runs remove(image, session=...) and takes the alpha channel as the soft mask (rembg_u2net.py:33-36). This is class-agnostic saliency — it segments the foreground subject, whatever it is.
  • Computes a confidence heuristic in _confidence_from_alpha (rembg_u2net.py:40) by penalising three things and averaging the penalties: too-little/too-much high-alpha coverage (rembg_u2net.py:43-46), high-alpha bleeding into the image border (rembg_u2net.py:48-55), and a fuzzy/uncertain boundary band measured via dilate-minus-erode (rembg_u2net.py:57-72). Final confidence = 1 - mean(penalties), clipped to [0,1] (rembg_u2net.py:74-77).

The provider protocol is (soft_mask, confidence) = predict(image) (protect_mask_providers/__init__.py:12-13); the service validates that shape/dtype/range contract (protect_mask.py:452-480).

The service: disk-cached, override-composited

ProtectMaskService (protect_mask.py:349) caches the auto mask only (not the override-composited result) keyed by image fingerprint + provider name. get (protect_mask.py:363):

  1. Canonicalises the framed raster to srgb_u8 (protect_mask.py:364; canonicalize_protect_mask_input at protect_mask.py:86 accepts uint8 or float32 HxWx3).
  2. Loads the cached .npz if present (protect_mask.py:372); on cache miss it calls the provider, validates, and writes the cache atomically via a .tmp rename (protect_mask.py:374-386, write at protect_mask.py:436-450).
  3. Applies the user override on top of the (cached) auto mask — apply_protect_mask_override at protect_mask.py:390.

Cache files live under data/generator/protect_masks/{fingerprint}_{provider}.npz (DEFAULT_PROTECT_MASK_CACHE_DIR protect_mask.py:25-27; path built protect_mask.py:410-412). clear() deletes all cached .npz (protect_mask.py:404-408). The image fingerprint is content-hash of the canonical raster (fingerprint_protect_mask_image protect_mask.py:102, 32-hex). A module-level _DEFAULT_PROTECT_MASK_SERVICE singleton (protect_mask.py:483) backs the chain resolver unless a service is injected.

Overrides (Wing D editing)

The auto mask can be edited two ways, both transported as a solve-scoped ProtectMaskOverride (protect_mask.py:53):

Override kindFieldCompositing rule
Brush strokesstrokes: tuple[BrushStroke, ...]protect strokes raise the mask (np.maximum), relax strokes lower it (mask * (1 - relax)) — protect_mask.py:335-343
Full raster uploadmask_png_pathgrayscale PNG replaces the base mask entirely (protect_mask.py:322-328)

apply_protect_mask_override (protect_mask.py:310) returns the composited mask plus debug maps (override_raster_mask, override_protect_strokes, override_relax_strokes). A BrushStroke (protect_mask.py:45) has mode ("protect"/"relax"), a polyline of points, radius_px, and opacity; strokes rasterise to a canvas with cv2 circles/lines in _stroke_to_mask (protect_mask.py:261). parse_protect_mask_override (protect_mask.py:131) validates the JSON transport strictly — only protect/relax modes (protect_mask.py:158), finite points, radius_px > 0 (protect_mask.py:182), opacity in [0,1] (protect_mask.py:186). Raster filenames are constrained to a server-managed basename inside the override dir — absolute paths, drives, and traversal are rejected (_normalise_override_mask_filename protect_mask.py:220-239; _resolve_override_mask_path re-checks the parent at protect_mask.py:209-217). Override dir: data/generator/protect_mask_overrides/ (protect_mask.py:28-30).

When F3 runs (double gate)

resolve_protect_mask_for_chain (protect_mask.py:486) returns None unless both gates pass:

  1. config.protect_subject_enabled is true (protect_mask.py:495).
  2. At least one operator sets supports_protect_mask = True (protect_mask.py:497).

The operators that opt in are C1, C2, B1 print-scale bilateral (operators/b1_printscale_bilateral.py:110), and B3 TV flatten (operators/b3_tv_flatten.py:127). The runner repeats this same double-gate before calling the resolver (pipeline/runner.py:714-717). The provider name comes from config.protect_mask_provider (default "rembg", protect_mask.py:508; config field pipeline/state.py:158) and the override from config.protect_mask_override (protect_mask.py:505-507; field pipeline/state.py:159).

F3: the protect weight (resolve_protect_blend_spec)

Source: preprocessing/protect_blend.py.

The mask is turned into a per-pixel editing weight by resolve_protect_blend_spec (protect_blend.py:20). The formula (protect_blend.py:42-47):

confidence_gate = clip((confidence - floor) / (1 - floor), 0, 1)
weight          = clip(strength * confidence_gate * mask, 0, 1)

So the protect weight scales with three things: the user strength (protect_subject_strength, validated to [0,1] at protect_blend.py:38), a confidence gate that ramps from 0 at the floor to 1 at confidence 1.0 (protect_confidence_floor validated to [0,1) at protect_blend.py:36), and the soft mask itself. A low-confidence auto-mask therefore self-attenuates toward no protection. Config defaults: protect_subject_strength = 1.0, protect_confidence_floor = 0.35 (pipeline/state.py:156-157).

F3: the blend (blend_aggressive_and_gentle)

Each protect-aware operator computes two versions of its edit — an aggressive pass and a gentle pass — and blend_aggressive_and_gentle (protect_blend.py:60) linearly interpolates them per pixel by the protect weight (protect_blend.py:88-90):

out = aggressive * (1 - weight) + gentle * weight

Weight 0 (background) = full aggressive edit; weight 1 (confident subject) = gentle edit. The function validates both images are float32 srgb_f32 HxWx3 of equal shape with a matching HxW weight (protect_blend.py:70-86).

Driving it (user-facing)

  • Reach a wider gamut warning / tone fit: enable C1 (achievable tonemap) and/or C2 (soft gamut compress). They self-resolve the F2 envelope; you do not configure F2 directly. Envelope width is determined by your palette, white sandwich, t_max, k_max, layer height, and corrections — those are the only knobs that move it (palette_metadata.py:64-72).
  • Protect the subject from heavy conditioning: turn on “protect subject” (protect_subject_enabled), which requires rembg installed (uv sync --group protect-mask-rembg). It only takes effect when at least one of C1/C2/B1/B3 is enabled.
  • Tune protection: raise protect_subject_strength toward 1.0 for stronger protection; raise protect_confidence_floor to ignore low-confidence auto-masks (the gate zeroes the weight below the floor).
  • Fix a bad auto-mask: paint protect/relax brush strokes, or upload a full-mask PNG. Overrides composite on top of the cached saliency mask, so re-running the same image is cheap (auto mask is cached; only the override re-composites).
