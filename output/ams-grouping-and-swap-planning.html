AMS grouping and swap planning

In one sentence: when the solved palette needs more colour filaments than fit in one AMS load, the generator partitions them into sequential swap groups (default greedy, optional Z-waste beam search), clips any over-budget thickness into the white cap, and emits human-readable swap instructions plus OrcaSlicer M600 pauses at export time.

This page covers everything that happens to solved layers after the colour stack is solved but before (and at) export, when the palette is too big for a single AMS. It serves both the user driving the wizard and the developer who has forgotten how swap.py and the grouping modules fit together.

Related: From solve to mesh the export pipeline · generator.swap · generator.grouping.greedy_optimize · generator.grouping.beam_search · generator.pipeline.runner · generator.facade · Print constraints

The slot budget

A printer has a fixed number of AMS slots. Some are reserved for white; the rest hold colour. The budget is computed on the solve config:

  • ams_slots (default 4) and white_slots (default 1) — pipeline/state.py:96, pipeline/state.py:97.
  • effective_white_slots() bumps the white reservation to 2 when the white base and white cap are different filaments (they need two physical slots), otherwise keeps white_slots — pipeline/state.py:220.
  • colour_slots() = ams_slots - effective_white_slots() — pipeline/state.py:226.

So with the default 4-slot / single-white setup you get 3 colour slots. Pick a white cap filament that differs from the base and you drop to 2 colour slots (one extra slot is spent on the second white). The same accessors exist on the facade SolveConfig (facade.py:326, facade.py:331) and are wired into the modules through state.config.

Grouping only triggers when the palette overflows. Each grouping module first filters the palette to active filaments — those present in the thickness maps with at least one pixel above 1e-9 mm — and returns immediately (a no-op) when len(active_fids) <= colour_slots (grouping/greedy_optimize.py:61, grouping/beam_search.py:568). If everything fits in one load, nothing on this page happens.

Where grouping runs in the pipeline

The webapp solve runs the staged backend (run_staged_backend_path), then runs the grouping module as a distinct post-solve step. In generator.pipeline.runner:

result = run_staged_backend_path(state, ...)      # runner.py:846
_finalize_staged_backend_state(state, result)     # runner.py:851
if has_grouping:
    config.grouping.group(state, progress)         # runner.py:855

Grouping does not run inside the staged solver — it is a separate module invoked afterwards (pipeline/runner.py:855). If it substitutes any pixels (n_substituted_pixels > 0), dE diagnostics are recomputed so state.diagnostics stays honest (pipeline/runner.py:856).

That is the command-line path, not the webapp. The webapp reaches the same greedy algorithm through the GreedyGrouping module wrapper. Both bottom out in swap.optimize_grouping.

Default greedy partitioner

GreedyGrouping.group delegates to swap.optimize_grouping (grouping/greedy_optimize.py:64), passing colour_slots, effective_max_layers(), the spline profiles, and the loaded filament registry. The result replaces state.thickness_maps with the substituted maps and stores the GroupingResult on state.grouping (grouping/greedy_optimize.py:76, grouping/greedy_optimize.py:77).

Inside optimize_grouping (swap.py:481):

  1. Active set, sorted by brightness. Active filaments are sorted dark-first by default (group_order="dark_first", swap.py:490), using approximate luminance from the registry hex value — 0.2126·R + 0.7152·G + 0.0722·B (swap.py:543). "light_first" reverses it (swap.py:551). Missing/unparseable hex falls back to luminance 128.0 (swap.py:546).
  2. Chunk into groups. plan_filament_groups slices the sorted ordering into consecutive groups of at most colour_slots (swap.py:553, sliced at swap.py:65).
  3. Budget clip → white cap. For each filament, any pixel whose thickness exceeds budget_mm = max_layers * layer_height is clipped to the budget, and the excess is added to the white-cap map MapKey.WHITE_CAP (swap.py:566–swap.py:572). This is the white-cap overflow substitution: out-of-budget colour becomes white so total Z stays bounded. n_substituted_pixels counts every clipped pixel (swap.py:573).
  4. The greedy optimiser returns total_de_cost = 0.0 — it does not estimate colour cost (swap.py:579).

Greedy is order-only: it sorts by brightness and chunks. It does not consider whether group-mates are spatially complementary.

Optional Z-waste beam-search packer

GroupBudgetGrouping (grouping/beam_search.py:436, registry name group_budget) explores many groupings and scores them by Z-waste instead of just chunking a sorted list. Enable it by setting group_budget in module state (facade.py:518).

Cost = Z-waste + band overflow + swap count + (optional) slot stability (_cost_group_budget, grouping/beam_search.py:125):

  • Z-waste — for each group, the band height is the max per-pixel sum of the group’s filaments; waste is band·n_pixels − sum — unused volume inside the loaded band (grouping/beam_search.py:160–grouping/beam_search.py:164). Spatially complementary filaments (thick at different pixels) pack tighter and waste less.
  • Band overflow — how far the summed group band heights exceed the colour budget max_layers·layer_height (grouping/beam_search.py:147, grouping/beam_search.py:167).
  • Swap count — len(groups) - 1 (grouping/beam_search.py:168).
  • Slot stability — penalises slot occupants changing between consecutive groups, only when its weight > 0 (grouping/beam_search.py:175, computed in _slot_stability_cost at grouping/beam_search.py:195).

Search structure (grouping/beam_search.py:561):

  1. Seed several diverse orderings — dark-first, light-first, alphabetical, an interleaved dark/light comb (only when ≥4 filaments), and reverse-alphabetical (_seed_orderings, grouping/beam_search.py:77). Each is chunked and scored into the beam (grouping/beam_search.py:575).
  2. Local search for up to max_iterations (default 10, grouping/beam_search.py:500) over a beam of width beam_width (default 16, grouping/beam_search.py:501): mutate by swapping/moving filaments between adjacent groups (_mutate_groups, grouping/beam_search.py:367), re-score, keep the best, and stop early when no improvement (grouping/beam_search.py:611).
  3. Optional dE re-rank — when de_scoring is on, the top candidates are re-ranked with an OKLab dE estimate of the colour lost to white-cap promotion (_estimate_substitution_de, grouping/beam_search.py:217; applied at grouping/beam_search.py:618).
  4. Apply the winner: build FilamentGroups via plan_filament_groups (grouping/beam_search.py:646) and clip overflow.

Overflow handling has two modes here. Default is the same per-filament clip-to-white-cap as greedy (_apply_substitutions, grouping/beam_search.py:290, called at grouping/beam_search.py:656). With in_group_substitution on, overflow is first offered to other filaments in the same group that have room, and only the leftover goes to white cap (_apply_substitutions_in_group, grouping/beam_search.py:313, called at grouping/beam_search.py:652) — this preserves more colour. The winning metric score is stored as total_de_cost on the result (grouping/beam_search.py:665).

FilamentGroup geometry

Both modules represent the plan as a list of FilamentGroup dataclasses (swap.py:18):

FieldMeaningAnchor
group_index0-based group orderswap.py:21
filamentsfilament IDs in this groupswap.py:22
z_start / z_endmm — bottom/top of this group’s colour bandswap.py:23, swap.py:24
slot_assignmentsfilament_id → AMS slot (1-based)swap.py:25

plan_filament_groups (swap.py:28) builds them: it re-filters to active filaments (swap.py:55), chunks into groups of colour_slots = ams_slots - white_slots (swap.py:50, swap.py:65), then walks the ordering accumulating a per-pixel cumulative stack starting at the white-base floor d_wb (swap.py:79). Each group’s z_start is the running cumulative.max() when its first filament begins (swap.py:94) and z_end is the max after its last filament (swap.py:101). Slots are assigned 1..colour_slots by position within the group (swap.py:109); white is implicitly the last slot (swap.py:104). Note plan_filament_groups takes ams_slots/white_slots directly, so callers pass colour_slots + 1 when they only know the colour budget (e.g. swap.py:529).

Export-time swap planning

Group geometry and swap instructions are produced at export time in server.get_swap_instructions — the GET /api/export/swap-instructions endpoint (server.py:5774). The solve-time grouping on state.grouping is only a starting point; export re-derives the plan against the current printer state. Sequence:

  1. Materialise export thickness maps and ordering — _prepare_export_materialization (server.py:835, called server.py:5793). Export can legitimately activate filaments the solve omitted.
  2. Read AMS capacity from current config, not the cached solve — ams_slots/white_slots come from _cfg() because the user may have changed printers after solving (server.py:5800–server.py:5802).
  3. Reconcile groups — reconcile_export_groups (swap.py:114, called server.py:5807). It keeps the solve-time layout when it still fits the current hardware, appends any export-only active filaments to the tail (swap.py:214), and falls back to a fresh plan_filament_groups when the old layout is too big or has too many groups for the current AMS (swap.py:168, swap.py:178). If AMS/white slot counts changed since the solve, the base groups are discarded first (server.py:5805, server.py:5806).
  4. Generate instructions — generate_swap_instructions (swap.py:272, called server.py:5822).
  5. Generate pause G-code — generate_orcaslicer_pause_gcode (swap.py:618, called server.py:5835).

Instruction text and M600

generate_swap_instructions (swap.py:272) emits a formatted plan: print dimensions, total height, per-group AMS slot assignments, and one SWAP block between consecutive groups. The swap height is the previous group’s z_end, converted to an approximate layer via round(swap_z / layer_height) (swap.py:403). For each swap it diffs the two groups’ slot_assignments and prints exactly which slot to unload/load (swap.py:413–swap.py:423), while reminding the user the white base/cap slots never change (swap.py:425–swap.py:429).

White slot bookkeeping: the base lives in the last AMS slot (base_slot = ams_slots, swap.py:354); when the cap is a different filament it takes ams_slots - 1, otherwise base and cap share the last slot (swap.py:355). Total lithophane height honours a per-pixel color_ceiling_map + wc_map surface when supplied, so the tallest colour stack and the thickest local cap need not coincide (swap.py:330–swap.py:339).

The actual pause command is M600. generate_orcaslicer_pause_gcode returns M600 ; pause for filament change at each between-group Z (swap.py:636), and generate_swap_instructions also embeds the same M600 snippet inline in its G-code section (swap.py:459). With a single group it returns "; No filament swaps needed" (swap.py:628). The number of mid-print swaps is always len(groups) - 1 (swap.py:353).

compute_filler_map — legacy CLI only

compute_filler_map (swap.py:583) pads every pixel to a uniform colour-stack height for a translucent filler filament. It has exactly one caller: the legacy CLI engine pipeline_cli.run, Step 4d, gated on filler_filament is not None (pipeline_cli.py:717). The webapp/staged backend never calls it — neither grouping module references it, and the __filler__ sentinel it writes is documented as “legacy CLI-only” (thickness_maps.py:15). Treat it as CLI-only / unused by the web app, not dead: it is reachable from python pipeline_cli.py ... --filler .... (The prompt’s “no observed caller” is too strong — the caller is the CLI engine, not the webapp solve path.)
