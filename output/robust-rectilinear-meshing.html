Robust rectilinear meshing

In one sentence: the generator turns each filament’s grid-aligned thickness map into a closed, slicer-safe triangle shell by walking every column’s vertical material intervals, assigning corner vertices to local occupied 2x2x2 sectors so the solid can touch itself at a point or edge without welding into a non-manifold blob, then merging flat faces, splitting bad fans, stitching open edges, separating coincident vertices, and filling residual holes — with a per-material fallback ladder (single body → topology-quarantine → Z-slab / adaptive-Z) that escalates only when a body fails the strict watertight check.

This page covers the geometry engine in generator/mesh/. It serves two readers: the user who just wants STLs that slice cleanly, and the developer who needs to know exactly how the shell is built and why a body sometimes splits into extra parts.

Where this runs (liveness)

The webapp’s export endpoint (server.py:5503, export_solve_bundle(...)) is the live entry point. server.py imports it at server.py:91. export_solve_bundle (mesh/post_solve_export.py:2120) loads the solve bundle, detects the solve mode, and dispatches on geometry source (mesh/post_solve_export.py:2245):

Geometry sourceBuilderWhite cap
EXACT_RASTERbuild_exact_raster_mesh_bundle (mesh/post_solve_export.py:1407)rectilinear interval map of the combined cap, with the fallback ladder
FIELD_DERIVEDbuild_field_derived_mesh_bundle_from_maps (mesh/post_solve_export.py:1528)hybrid: rigid rectilinear guard + freeform surface

Both builders call the same color-stack mesher (_base_and_color_objects, mesh/post_solve_export.py:1291), which is reused by the field path at mesh/post_solve_export.py:1577. The field path additionally reconstructs the cap thickness map from solve fields (reconstruct_field_white_cap_from_arrays, mesh/post_solve_export.py:2272) and meshes it with build_hybrid_white_cap_meshes (mesh/post_solve_export.py:1592).

All seven source modules named below are reachable from this one entry point — confirmed by import-and-call grep, not by module headers (which are stale: several still frame the code as “future webapp wiring” or a “sandbox” trial even though the webapp path is live).

The core mesher: mesh_interval_map

mesh_interval_map (mesh/rectilinear_interval.py:778) is the workhorse. It takes a floor map and a thickness map (both H×W, in mm) plus the XY pitch_mm, and returns one closed single-material trimesh.Trimesh plus a RectilinearMeshStats audit record (mesh/rectilinear_interval.py:34). Every color layer, the exact-raster cap, and the hybrid rigid guard go through it.

1. Z levels and per-slab occupancy

A column is “active” when its thickness exceeds eps (mesh/rectilinear_interval.py:813). The set of distinct floor-and-top heights across all active columns becomes the global Z level array (_global_z_levels, mesh/rectilinear_interval.py:122) — so every height where any column starts or stops material is a shared cutting plane. Each gap between consecutive Z levels is a “slab”; _occupancy_by_slab (mesh/rectilinear_interval.py:131) marks, per column, which slabs are filled, using searchsorted on the column’s floor and top. The result present is an H×W×K boolean occupancy grid.

Optional z_snap_decimals rounds floor/top to a fixed decimal grid before level extraction (mesh/rectilinear_interval.py:802), with top clamped >= floor so rounding can’t invert an interval (mesh/rectilinear_interval.py:807). The export config defaults to z_snap_decimals = 6 (mesh/post_solve_export.py:212); the hybrid config defaults to 6 as well (mesh/hybrid_white_cap.py:47). Snapping makes adjacent layers share exact plane heights so their walls coincide instead of leaving a sub-micron crack.

2. Exposed faces

_neighbor_masks (mesh/rectilinear_interval.py:163) shifts present in all six directions. A face is emitted wherever a filled cell has an empty neighbor: present & ~neighbors[dir] for east/west/north/south/top/bottom (mesh/rectilinear_interval.py:844). _append_quads (mesh/rectilinear_interval.py:186) turns each exposed cell-face into a quad, recording four corner grid indices (row, col, z) plus a 3-bit local code identifying which of the eight surrounding cells owns that corner. Corner winding order deliberately mirrors the legacy per-pixel emitter (mesh/rectilinear_interval.py:209).

3. The 2x2x2 sector trick (the heart of it)

This is the mechanism that keeps a self-touching solid closed instead of pinched. Around every grid corner there are eight surrounding cells, forming a 2x2x2 neighborhood. _corner_patterns (mesh/rectilinear_interval.py:149) packs the 8 occupancy bits of that neighborhood into one 8-bit code per corner (stored in a uint16 array, but only the low byte is ever set, so the lookup tables are sized 256). SECTOR_LOOKUP (mesh/rectilinear_interval.py:114, built by _sector_lookup, mesh/rectilinear_interval.py:80) is a 256×8 table that, for each of the 256 patterns, runs a connected-component flood over the occupied corners (6-connected adjacency, mesh/rectilinear_interval.py:91) and labels which sector each occupied cell belongs to.

When two material regions of the same filament meet only at a corner point or along a single edge, the 2x2x2 pattern has two disconnected occupied components, so that corner gets two distinct sector labels. Each face vertex is keyed by (row, col, z, sector) (mesh/rectilinear_interval.py:916), so the two regions get separate vertices at the same coordinate instead of one shared vertex. That prevents a single point/edge from being incident to too many faces — the classic non-manifold pinch that slicers reject. SECTOR_COMPONENT_COUNT (mesh/rectilinear_interval.py:115) precomputes how many sectors each pattern splits into; _split_count (mesh/rectilinear_interval.py:455) sums the “extra” sectors across the whole grid for the diagonal_or_corner_splits stat.

4. Vertex assembly

Quad corners are encoded into a single integer key (((row·(W+1)+col)·K + z)·8 + sector) (mesh/rectilinear_interval.py:916), uniquified, and split into two triangles per quad (mesh/rectilinear_interval.py:925). The key is decoded back into (x, y, z) world coordinates by reversing the packing (mesh/rectilinear_interval.py:935), with y flipped to image-up orientation (mesh/rectilinear_interval.py:943). The mesh is built process=False (no auto-weld) and only duplicate/degenerate faces are dropped (mesh/rectilinear_interval.py:949).

5. Horizontal-face merge (optional, default on)

With merge_horizontal_faces=True (config default mesh/post_solve_export.py:211), top and bottom faces are not emitted as per-cell quads; only the four side directions are (mesh/rectilinear_interval.py:863). Instead, _append_horizontal_merged_faces (mesh/rectilinear_interval.py:409) treats each slab’s top/bottom mask as a region to be triangulated as a whole, drastically reducing triangle count on flat plateaus.

Per connected component (ndi.label with 4-connectivity, mesh/rectilinear_interval.py:329), _component_ring_groups (mesh/rectilinear_interval.py:250) traces the exact pixel-corner boundary rings with trace_mask_grid_rings (mesh/grid_rings.py:9) rather than Shapely booleans — deliberately, so long collinear boundary runs are kept and the merged face shares exact edge vertices with the unmerged side-wall quads (mesh/rectilinear_interval.py:255). Rings are grouped into [outer, holes...] by signed area (mesh/rectilinear_interval.py:263) and point-in-polygon containment (mesh/rectilinear_interval.py:273). The polygon is triangulated by shapely.constrained_delaunay_triangles (mesh/rectilinear_interval.py:357), falling back to mapbox_earcut if that raises (mesh/rectilinear_interval.py:362). Every triangle vertex is re-mapped back to its occupied 2x2x2 sector via _component_vertex_key (mesh/rectilinear_interval.py:279) so merged faces use the same sector-keyed vertices as the walls. flip controls bottom-vs-top winding (mesh/rectilinear_interval.py:398).

trace_mask_grid_rings itself (mesh/grid_rings.py:9) walks boundary half-edges with a left-turn rule (mesh/grid_rings.py:38) to produce oriented loops; _trace_mask_grid_rings is an alias (mesh/grid_rings.py:86).

The cleanup pipeline (post-construction, in order)

After the raw shell exists, mesh_interval_map runs a fixed sequence (mesh/rectilinear_interval.py:957–991):

StepFunctionWhat it doesAnchor
Overfull fan split_split_overfull_edge_fansonly on the merged path: splits the face fan at any edge used by >2 faces, cloning the shared vertex per connected fan group (union-find over incident faces)mesh/rectilinear_interval.py:559, called :958
Open-edge stitch_stitch_duplicate_open_edgeswelds geometrically-coincident open (count-1) edge pairs left by sector splitting, via union-find on vertex coords rounded to 9 decimalsmesh/rectilinear_interval.py:652, called :961
Re-split (merged)_split_overfull_edge_fanssecond fan split after stitching, merged path onlymesh/rectilinear_interval.py:963
Separate duplicates_separate_duplicate_verticesnudges topologically-distinct coincident vertices apart by a sub-micron XY offsetmesh/rectilinear_interval.py:722, called :965
Hole fill (≤2 passes)trimesh.repair.fill_holesfills any remaining count-1 edges, then re-runs fan-split + separation on added facesmesh/rectilinear_interval.py:972–989
Fix normalstrimesh.repair.fix_normalsconsistent outward winding (fix_normals defaults True)mesh/rectilinear_interval.py:990

The unmerged quad path skips the first fan split entirely (fan_splits = 0, mesh/rectilinear_interval.py:960) because sector-keyed quads can leave duplicate open edges but cannot create an over-full edge — see the inline rationale at mesh/rectilinear_interval.py:951. Merged horizontal triangulation can produce unpredictable fans, so the splitter is kept for it.

Why separate, don’t weld

_separate_duplicate_vertices (mesh/rectilinear_interval.py:722) exists because STL does not preserve vertex identity — a slicer re-welds any two vertices at the same coordinate on import, which would undo the sector split and recreate the pinch. So at already-split contacts it shifts each duplicated vertex by offset_mm along the in-plane direction toward its incident-face centroid (mesh/rectilinear_interval.py:767), introducing a tiny XY-only geometric gap (Z is never touched) without changing topology. Default offset is 0.001 mm (mesh/rectilinear_interval.py:787, config mesh/post_solve_export.py:213). The hybrid module carries its own identical copy of this routine (mesh/hybrid_white_cap.py:519).

The hole-fill loop only triggers when count-1 (open) edges remain (mesh/rectilinear_interval.py:974) and stops early if a pass adds no faces (mesh/rectilinear_interval.py:979); newly-added fill faces get the same fan-split + separation treatment (mesh/rectilinear_interval.py:984).

Mesh quality gates

check_mesh_quality (mesh/quality.py:20) is the product quality summary: it counts per-edge face references (edge_face_counts, mesh/quality.py:8), reports n_open_edges (count == 1) and n_pinch_edges (non-2 minus open) plus is_watertight. A mesh passes when watertight with zero open and zero pinch edges (_quality_passes, mesh/post_solve_export.py:328).

Because the exported (separated) mesh must survive a slicer’s reload-weld, there is a stricter second gate. _strict_processed_quality (mesh/post_solve_export.py:336) rebuilds the mesh with trimesh process=True — which does weld coincident vertices, simulating the slicer — and re-checks edges. _strict_processed_quality_passes (mesh/post_solve_export.py:362) requires watertight with zero strict-non-2 and zero open edges. A body is only accepted as-is when it passes both gates (color: mesh/post_solve_export.py:1343 via _color_mesh_quality_passes at :1098; white cap: mesh/post_solve_export.py:1454). Passing the loose gate but failing the strict one is the signal that “this will pinch after import” — and that triggers the fallback ladder.

The white-cap fallback ladder

When a single-body interval mesh fails the strict gate, the orchestrator escalates by splitting the body into multiple same-material parts that each survive welding. The escalation differs between the white cap and color layers.

White cap (exact-raster path), build_exact_raster_mesh_bundle

The decision is at mesh/post_solve_export.py:1454:

  1. Single interval — if force_exact_white_cap_slabs is off and both gates pass, ship the one body (selected_strategy = "single_interval", mesh/post_solve_export.py:1459).
  2. Forced slabs — if force_exact_white_cap_slabs is on (config default False, mesh/post_solve_export.py:214), skip straight to constant-Z slabs via _build_exact_white_cap_slabs (mesh/post_solve_export.py:499, dispatched :1471). Each gap between snapped Z levels becomes one flat-bottomed slab body.
  3. Topology quarantine — otherwise, _build_white_cap_quarantine_parts (mesh/post_solve_export.py:774). This cleaves only the risky columns into a second same-material body, leaving the rest intact. If that yields a ready result, ship it (mesh/post_solve_export.py:1494).
  4. Adaptive-Z partition — if quarantine still fails, _build_exact_white_cap_adaptive_parts (mesh/post_solve_export.py:595, dispatched :1500).

Topology quarantine, _build_interval_topology_quarantine_parts

The shared quarantine engine (mesh/post_solve_export.py:807) first asks topology_risk_column_mask (mesh/rectilinear_interval.py:485) which solve-grid columns sit adjacent to a multi-sector corner (a SECTOR_COMPONENT_COUNT > 1 vertex touching an occupied slab, mesh/rectilinear_interval.py:530–541). With no risk columns it reports no_risk_columns and bails (mesh/post_solve_export.py:834). Otherwise it tries six partitions of those risk columns — row_even/odd, col_even/odd, checker_even/odd (mesh/post_solve_export.py:847) — meshing the “main” body (risk cells removed) and the “quarantine” body (only risk cells) separately (mesh/post_solve_export.py:866). It accepts the first partition where both bodies pass both gates (mesh/post_solve_export.py:963); status is "ready" only if no part failed (mesh/post_solve_export.py:967). The idea: separating the touching cells into a different body means their welded-together vertices belong to different shells, so the pinch never forms.

Adaptive-Z partition, _build_exact_white_cap_adaptive_parts

This recursively bisects the Z range (build_range, mesh/post_solve_export.py:651). It clips the cap to [z0, z1] with _clipped_interval_map (mesh/post_solve_export.py:571), meshes it, and if it passes both gates accepts it as one part (mesh/post_solve_export.py:689). If it fails and spans more than one Z level, it splits at the midpoint and recurses (mesh/post_solve_export.py:751). A single-level range that still fails is shipped anyway tagged white_cap_slab_failed (mesh/post_solve_export.py:743) — the strategy emits everything and records leaf failures rather than aborting the export.

Color layers, _base_and_color_objects

Color materials use a slightly different ladder (mesh/post_solve_export.py:1346):

  1. Single body if both gates pass (mesh/post_solve_export.py:1343).
  2. Else topology quarantine via _build_color_quarantine_parts (mesh/post_solve_export.py:1102); shipped if status == "ready" (mesh/post_solve_export.py:1356).
  3. Else Z-slab fallback via _build_color_z_slab_parts (mesh/post_solve_export.py:985) — one same-material body per snapped material plateau (mesh/post_solve_export.py:1021).

The white base plate is never an interval mesh; it is a single make_box plate (generate_flat_plate, mesh/primitives.py:50; called mesh/post_solve_export.py:1304).

The hybrid white cap (field-derived path)

build_hybrid_white_cap_meshes (mesh/hybrid_white_cap.py:621) builds the cap as two same-filament bodies so the layer-exact region near the color stacks stays rigid while the rest follows the smooth field surface:

  • Rigid guard — a rectilinear interval body (mesh_interval_map again, mesh/hybrid_white_cap.py:651) that exactly caps the color columns and laterally shields them out to guard_width_mm. Its intervals come from derive_hybrid_white_cap_intervals (mesh/hybrid_white_cap.py:150): guard floor sits on the color top (mesh/hybrid_white_cap.py:194), and the lateral guard domain is the air ring within guard_width_mm of color (mesh/hybrid_white_cap.py:176) raised to the neighboring color top (mesh/hybrid_white_cap.py:187).
  • Freeform surface — mesh_freeform_cap_surface (mesh/hybrid_white_cap.py:402) builds a continuous top+bottom skin over the optically-free region. Per active cell it emits two top triangles and two bottom triangles (mesh/hybrid_white_cap.py:473) plus boundary walls (mesh/hybrid_white_cap.py:480). It has its own 2x2x2-style diagonal handling: at a checkerboard contact (NW+SE occupied, NE+SW empty, or the mirror) it assigns the shared corner a sector bit so the two diagonal cells get distinct vertices (mesh/hybrid_white_cap.py:432, :439), counted as diagonal_corner_splits. Corner heights are averaged from incident cells (mesh/hybrid_white_cap.py:450), then the surface is separated + hole-filled like the rigid path (mesh/hybrid_white_cap.py:503).

validate_hybrid_white_cap_intervals (mesh/hybrid_white_cap.py:298) sweeps layers and checks the guard+free union never removes reference-white coverage and never leaves color exposed; guard_coverage_status is "pass" only when zero exposed-color and zero removed pixels (mesh/hybrid_white_cap.py:391). The result’s status property (mesh/hybrid_white_cap.py:116) returns mesh_quality_failed if any cap body has open/pinch edges, else coverage_review if coverage didn’t pass, else ready.

Field reconstruction (upstream of the hybrid mesh)

reconstruct_field_white_cap_from_arrays (mesh/field_white_reconstruction.py:254) converts solve-bundle scalar fields into the cap thickness map the hybrid mesher consumes. It picks a target upper surface per solve mode (_target_upper_surface, mesh/field_white_reconstruction.py:229: luminance uses white_cap_total_thickness_map; standard uses a boundary field plus optional detail, mesh/field_white_reconstruction.py:163), upsamples to a finer grid by field_scale (default 4, mesh/field_white_reconstruction.py:32), then collapses layer-by-layer into integer layer counts (mesh/field_white_reconstruction.py:299). Each layer’s white mask is cleaned by _cleanup_white_mask (mesh/field_white_reconstruction.py:92): tiny internal air voids are filled and tiny positive features removed, with thresholds from GeometryPrintabilityPolicy (mesh/field_white_reconstruction.py:268). It stops before mesh construction by design (mesh/field_white_reconstruction.py:5).

Printability policy

Thresholds are resolved once into GeometryPrintabilityPolicy (mesh/geometry_policy.py:21). The solve-grid pitch is the hard minimum positive width — a 0.2 mm grid means 0.2 mm minimum feature (mesh/geometry_policy.py:23). Derived defaults: lateral guard width defaults to that min width (mesh/geometry_policy.py:47), max internal empty-hole area defaults to 0.5·width² (mesh/geometry_policy.py:54), min positive feature area to width² (mesh/geometry_policy.py:64). GeometryExportPolicy (mesh/geometry_policy.py:95) bundles pitch/layer-height/white-base and enforces that any supplied printability policy agrees on the solve pitch (mesh/geometry_policy.py:120). These policy objects do not read UI state — callers resolve settings first and pass resolved numbers in (mesh/geometry_policy.py:1).

The audit record

Every interval mesh emits RectilinearMeshStats (mesh/rectilinear_interval.py:34), serialized via as_dict (mesh/rectilinear_interval.py:56) into the export manifest’s per-object stats. Useful fields when debugging a non-manifold report: diagonal_or_corner_splits (sector splits), nonmanifold_edge_fan_splits, duplicate_open_edge_stitches, separated_duplicate_vertices, filled_hole_faces, and the three topology_risk_* preflight counts (mesh/rectilinear_interval.py:466). The fallback reports also carry single_interval_quality / single_interval_strict_processed_quality so you can see why the single body was rejected before the ladder kicked in.
