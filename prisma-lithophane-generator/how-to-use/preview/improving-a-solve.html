Improving a Solve

Improving a Solve

Jul 27, 20268 min read

A disappointing preview does not necessarily mean that the solver failed. The selected palette may be a poor fit for the image, or one small part of an otherwise good solve may need a controlled nudge. The most reliable procedure is to explore broadly with palettes first, then make narrow settings changes only after choosing a promising palette.

There is no single numerical score that captures everything people notice in an image. Use Suggest dE and RMSE % as screening information, but choose by comparing the predicted images at full size.

The short version

  1. Solve several strong palette suggestions with the same settings.
  2. Keep the palette with the best overall cohesion, even if another run has a slightly better score.
  3. Identify one specific defect in that run.
  4. Make one small settings change aimed at that defect.
  5. Solve again and compare both runs side by side.
  6. Keep the change only when the preview is meaningfully better.

If the whole image feels wrong, return to the palette before changing many settings. If the image is already close and only one feature is wrong, keep the palette and use the targeted adjustments below.

The ordinary starting posture

Prisma’s defaults incorporate the broadly useful settings from the production-scale comparison:

  • Appearance budget: 0.004 dE
  • Smoothing radius: 1.0 mm
  • Min Cap Layers: 2
  • Boundary mutation: enabled, with one pass
  • White-point rescale: disabled

These defaults are intended to produce a strong first solve, not to be universally optimal. In particular, white-point rescaling remains opt-in because it can produce a major improvement when an image needs greater internal color coherence, but it changes the image’s absolute color target and is not a universal win.

Optional refinement profiles

Prisma includes two evidence-backed alternatives under Settings → Profiles…:

  • Refinement — Balanced is the safer first comparison. It enables Print-Scale Smoothing, uses a 0.4 mm solve pitch, 2.0 mm cap smoothing, a 3.5 mm thickness limit, nine detail layers, and two boundary-mutation passes.
  • Refinement — Strong changes the solve more aggressively. It uses the same preprocessing and cap policy, with a 3.0 mm thickness limit, four colors per region, coarser first-stage planning, five detail layers, and three mutation passes.

These are conditional alternatives, not higher quality levels and not automatic fallbacks. Compare Balanced first when the ordinary result is promising but unresolved; try Strong when you want a more substantial alternate interpretation. Loading either profile intentionally changes the solve pitch and smoothing radius along with its other settings.

First, compare palettes

Palette choice usually changes the result more than a reasonable adjustment to one solver setting. Prisma’s first suggestion is a strong starting point, but the suggestion order estimates color coverage before the full solve. It cannot completely predict region boundaries, white-cap seams, or whether a coherent color cast will look better than one locally accurate but distracting color.

Use this palette pass:

  1. In Palette → Auto-Suggest, set Suggestions to at least 5.
  2. Add the first several suggestions at the recommended size to the Palette Deck. Also consider the size-ladder cards when you want to compare using fewer or more colors.
  3. Leave the image and settings unchanged.
  4. Select each palette and press Solve.
  5. In Preview, show the runs together and click each predicted image when you need the full-resolution view.

Judge the image in this order:

  • Does the image read correctly as a whole?
  • Are broad skies, walls, skin, fabric, or other familiar surfaces internally coherent?
  • Is any small region so wrong that it attracts attention?
  • Are there conspicuous seams, false outlines, or speckled patches?
  • Only then, which remaining run follows the source most closely?

A lower Suggest dE or RMSE % is useful evidence, not a command. A slightly less literal palette can look better when its errors are consistent across the image.

Then, name the defect

Avoid changing settings merely because a run is not perfect. Describe the visible problem first and choose the smallest matching intervention.

These are starting points, not a recipe to apply all at once.

Why some useful changes score worse

Human vision is unusually tolerant of a coherent change in lighting or overall color cast. The same object can look normal at noon or near sunset even though its measured colors are very different. An erratic color change within one familiar object is much more distracting.

That is why White-point rescale can make a preview look better while its literal source-error score gets worse. It may sacrifice absolute color matching to bring outlier regions into agreement with the rest of the solved image. Keep it off when the ordinary solve is already coherent; compare it when pale, neutral, or familiar regions disagree with one another.

The same principle applies when choosing palettes. Prefer the result that forms one believable image over a result that matches one isolated color perfectly but makes that region look detached from its surroundings.

Use cap layers deliberately

Min Cap Layers is more than a coverage safeguard:

  • 2 layers is the ordinary default; it gently softens region boundaries and reduces the perceptual prominence of lateral white-cap coverage.
  • 3–5 layers can calm dark or saturated areas that look too forceful.
  • 1 layer preserves the greatest available color height when maximum contrast or saturation matters more.

Additional minimum cap layers do much less to already-light regions because those regions were not using much color height in the first place. Watch the predicted image rather than assuming the whole result will become uniformly washed out.

Nudge a nearly excellent solve

When only one small feature is wrong—especially a face or another familiar shape—the solver may have made a locally reasonable choice that people notice as a defect. Large global changes are risky at this point.

Instead, create a few nearby alternatives:

  • use Noise Reduction: Light to make a very small change to the source entering the solve;
  • add one Mutation pass so an existing region boundary gets another chance to move;
  • or add one Min Cap Layer to slightly soften the color-height result.

Try these separately before combining them. Their purpose is not to improve every metric; it is to give a nearly successful solve another path around one objectionable local result.

Changes that deserve caution

  • Do not change many unrelated controls in one run. You will not know which change helped, and interactions can hide a new defect.
  • Do not keep increasing smoothing. A larger radius can help a calm area while creating a dark lateral-cap outline around a neighboring raised region.
  • Do not enable White-point rescale by default for every image. It is powerful precisely because it changes the rendering target.
  • Do not chase a tiny score improvement when the image looks less coherent.
  • Do not use strong preprocessing merely to remove normal photographic texture. Overprocessing can replace natural variation with broad artificial patches.

A repeatable comparison loop

Name runs for the question they test—for example, Sky – palette 3, Cap budget 0.004, or White-point rescale. Keep the current best run visible beside each new candidate. Inspect both the whole composition and the problem area at full size.

Stop when the remaining differences are merely different compromises. The predicted appearance does not need to reproduce noisy source pixels exactly; the goal is a coherent image without a conspicuous local failure.

This guidance comes from production-scale comparisons across varied real images, palettes of three to five colors, and expert visual review. The controlled study used no-swap palettes and a 0.4 mm nozzle with 0.4 mm solve pitch. Treat the procedures as strong starting points rather than guarantees for every image, palette, or print setup.
