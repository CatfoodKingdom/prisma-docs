Preview

Oct 07, 20269 min read

The Preview tab is where you inspect and compare results. You start a solve, Prisma works out the filament stack for every point, and the results land here for inspection — before you’ve spent any plastic.

For an explanation of how Prisma chooses the filament layers, see How It Works.

Starting a solve

Select one or more Palette Deck cards, then press Solve in the top bar from any workflow page. Prisma keeps your current workspace open. One selected card starts one solve; 2–10 selected cards show Solve (N) and start a batch in deck order. With no selection, Solve is disabled.

Click a card to select it alone. Shift-click selects a range; Ctrl-click toggles individual cards. Drag a selection rectangle from the empty space above or below the deck cards, then use Ctrl-click to exclude any you do not want. Progress appears in the Solve progress or Solve Queue window. You can keep editing and add another solve while earlier work is running; each solve keeps the image, palette, and settings you submitted. See Solve Queue for progress, cancellation, and waiting solves.

For an exact repeat, Prisma may reuse compatible completed work instead of solving again. This can come from the current session or a compatible automatic save after restart. Prisma can also recognize a matching solve already waiting or running. An Already solved notice means that a matching result is available; open Preview to review it.

Before starting, Prisma checks the current Settings, active printer, Palette, stack geometry, and border thickness. A blocking problem tells you what must be fixed. Prisma also checks whether the requested physical image size lands on whole Solve Pitch cells. If it does not, Lithophane Dimensions shows the current and proposed sizes, both with and without the border. Resize accepts the proposed size and continues the same solve. Cancel leaves the requested dimensions unchanged. A print larger than the printer area opens Larger Than Printer Area; Use Current Size is available only when Prisma permits it.

A batch keeps the same image, settings, preprocessing, printer/nozzle, model library, and white base/cap filaments, then changes only the colored palette. It can compare deck cards of different origins and sizes. Prisma deliberately does not choose a winner.

Viewer

Select a Solve Timeline card to see its result in the Viewer. View Mode switches between the predicted appearance, the white cap, the color regions, and more. Each view is described in Preview Card Modes; the extra views behind Advanced are in Advanced Modes.

Use Zoom to enlarge the image from its fitted size, or hold Ctrl and turn the mouse wheel over it. Drag an enlarged image to move around it. Fit returns to the whole image. When several results are selected, their zoom and movement stay together so you can compare the same area in each one. Explorer also uses a shared height when comparing results.

Drag the divider beside Inspector to give the Viewer more room, or the divider above Solve Timeline to change its height. In the Timeline, drag a card’s resize handle to change card size; double-click the handle to return to automatic sizing.

One thing to know up front: the result can look blocky compared with the photo. That view shows the solve grid honestly rather than inventing image detail between solved points. A field-derived white-cap export may reconstruct a smoother physical cap surface, but it does not create new color decisions beyond the solve resolution.

Solve Timeline and Inspector

Every accepted solve becomes a card in the Solve Timeline. Show Results For chooses the source image whose runs you want to review. Group By → Palette keeps runs together by palette; None keeps them in order. Each run retains its Source, Image Setup, Print Setup, Palette, and Solve Settings, even when it was cancelled or failed before producing a result.

Select a run to open its Inspector. Current shows the full summary; Compact concentrates on dimensions and settings differences. In Current, Details on Image & Adjustments, Printer, Palette, or Settings opens the attached detail drawer. Historical names and colors remain those used by the run; a separate availability note explains whether that part can still be applied with the resources installed now.

Solve Settings are initially compared with your startup Settings Profile. Compare to chooses a different saved profile as the common reference for every inspected run. Loading a different profile for the next solve does not move this reference. Unsaved profile edits are not used in the comparison. In Settings Details, Settings shows the captured values and Compare shows them against the reference profile. Advanced: On reveals the finer controls. Details show the settings that applied to the inspected run; values belonging to disabled features or another solve mode are left out.

Click a card to select that run alone. Ctrl-click (Command-click on macOS) adds or removes individual runs; Shift-click selects a range. Selecting two or more results puts them together in the Viewer. Click one of those images to show its Inspector without removing the others from the comparison. Export selects one completed run at a time.

Use the star on a card or in Inspector to mark a promising run. Starred only filters the Timeline for the chosen source image; starring does not save the run. The card and Inspector also offer Save, Delete, and access to the captured settings. Delete asks for a second click. Cancel a queued or running solve in Solve Queue before removing its card.

Cards can show Queued, Solving, Cancelled, or Failed. A failed card keeps its concise error and can be deleted; later batch items continue. To keep a completed run deliberately, save it. Save is available after the solve finishes. Clear removes the cards from the current Solve Timeline display for the selected source image, including cards hidden by Starred only. It asks for a second click and is unavailable while a solve or export is active. It does not delete saved runs, automatic saves, or print files already generated.

Review, reuse, and make a new solve

These are deliberately different operations:

  • Review reads the run’s captured setup and result. It does not change the workspace and does not require the same Model Library release to be active now.
  • Export or reprint uses the completed run and its saved result. It does not recompute the result against today’s library or settings.
  • A section drawer’s Use… action recalls only that section. For example, Use This Palette preserves its order, while Use These Settings also restores the Base/Cap Filament choices captured with Settings.
  • Use as Starting Point reconstructs every compatible part of the run as one editable workspace. The confirmation lists what will be applied and what must remain unchanged. Prisma then moves to Image so you can review or modify the setup. It never starts a solve.
  • Pressing Solve afterwards creates a new solve from the reconstructed state and the resources active now.

Exact Framing requires the same source content and pixel geometry. A Palette requires all of its filament IDs in the active Model Library. Print Setup needs a current printer/nozzle that supports its Extrusion Width, Layer Height, and image footprint. An incompatible part is left unchanged and reported; it does not make the historical run unavailable for review or export.

Saving and loading solves

Press Save on a card and give it a name to create a durable Saved Run — its source image, framing and appearance, Palette, Settings, and completed result. Names such as Run 7 are reserved for the automatic labels Generator gives new live cards, so choose a descriptive name instead.

Load at the top of Solve Timeline opens Saved Runs. Rows marked Saved are explicit durable saves. Rows marked Autosave are temporary, best-effort copies made after successful solves. Prisma keeps only a recent set, older Autosaves can be removed automatically, and Clear Temp Files removes them. An Autosave may survive a process restart, but it is not a durable save; use Save when you intend to keep a run.

Select a row and use Load to return the complete run to Solve Timeline and Preview without solving again. Your current image, settings, and Palette Deck stay as they are. To begin new work from the loaded run, use its Inspector’s Use as Starting Point or a section’s Use… action. Use Settings in Saved Runs loads only the captured Settings as a session-only TEMP Settings Profile. Save promotes an Autosave to a durable Saved Run, Rename manages a Saved row, and Delete removes the selected Saved or Autosave record. Download writes a portable archive, while Load from file… imports one — useful for backup or moving a run to another computer.

Reloading the browser reconnects to the current workspace and its retained runs. To return after restarting Prisma, save the whole workspace or save an individual run. Autosaves are temporary even when one happens to remain available after a restart. Use Save, Download, or export the print files for anything you must retain.

Prisma keeps the archived source with the loaded card. If you recall its image setup, Prisma can reuse an identical Image Library photo or show a temporary Saved run source on the Image page. Loading alone does not select it. Re-saving the card keeps the archive’s image even if a matching Library file is later changed or deleted.

Experimental GPU solves

In Config → Preferences → Solve, enable Use GPU for solves and press Apply. It is off by default and applies to newly submitted solves without restarting Prisma. The tested setup is Windows with a Ryzen 9 9900X, 64 GB RAM, and Radeon RX 9070; it requires the optional GPU solver components and compatible AMD drivers. Other configurations are untested.

Some parts of a solve still use the CPU. Requests the GPU cannot handle use the CPU, and a GPU problem can cause Prisma to retry on the CPU. Inspector records how the run was solved; enabling GPU does not replace an existing completed result. The setting is separate from GPU palette suggestions and exports.

When the result isn’t right

Compare the predicted view against the source and trust your eye. Start with several strong palette suggestions before tuning settings: palette choice usually changes more than one reasonable solver adjustment. Once you have a promising palette, name the specific defect, change one matching control, solve again, and compare both runs side by side.

Improving a Solve provides the full procedure and targeted starting points for chunky gradients, white-cap seams, overly bold dark regions, incoherent color casts, smoothing outlines, and isolated local defects.
