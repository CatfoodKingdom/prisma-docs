Runs with Swaps

Jul 23, 20264 min read

A normal run keeps every colored filament loaded from the first color layer to the last. When the palette exceeds the active printer’s color slots, Prisma instead divides those filaments among a sequence of fixed-height bands. The printer pauses at each band boundary so the next set of colors can be loaded.

This happens automatically during the solve. There is no user-facing planning choice and no alternate swap method.

Why the bands must be flat

A slicer pause occurs at one Z height across the entire panel. The lower set of filaments therefore has to finish at the same height everywhere before any slot can be reassigned.

The colored stacks do not naturally end on a flat plane. Prisma fills the unused height inside each band with the same white used for the base and cap. Every point then reaches the band’s fixed ceiling, making the next set of colors physically printable above it.

That white fill is also the central compromise. It changes the light passing through the color stack, usually making some combinations lighter or less saturated. The bands consume part of Max Total Thickness as well, leaving less freedom for the cap and color recipes. A swap run is therefore more constrained than an otherwise identical run with every color continuously available; it cannot improve the underlying optical search space, even when the larger palette makes the final result better than a smaller no-swap palette.

The scout solve

Prisma cannot choose useful band heights from filament names alone. It first performs a reduced-resolution scout solve with the full palette and no bands. The scout estimates how much of each filament the image wants and where those thicknesses occur.

The palette is already in the canonical dark-first print order. Prisma considers valid ways to assign those filaments to the available color slots across the required number of bands. Each candidate band’s height is estimated from almost all of its active scout usage and quantized to whole printed layers. The chosen plan minimizes total band height first and predicted white fill second.

This is why filaments that are heavily used in different parts of the image may share a compact band, while filaments that need to stack thickly in the same places tend to require more height.

The final constrained solve

The scout does not become the printed result. Once the band plan is fixed, Prisma builds new color lookup tables whose recipes obey those bands and already include the required white fill. The full-resolution solve then runs against those tables.

Including the fill during the final solve matters: the solver evaluates the color that the physically printable, white-filled stack will transmit. It does not solve an unconstrained image and patch the bands in afterward.

The completed run stores the band assignments, their exact layer counts, and the resulting pause heights. That plan is part of the run just like its palette and cap settings.

From bands to Swap Instructions

Each pause height is the white-base thickness plus the completed band heights below it. On Export, Swap Instructions turns the stored plan into:

  • the initial filament assigned to each slot;
  • the Z height for every slicer pause;
  • which filament to unload and load in each affected slot; and
  • which slots remain unchanged.

Export presents the plan; it does not optimize it again. If the active printer has fewer usable slots than the completed solve assumed, the plan is incompatible and the run must be solved again with the correct printer configuration.

The practical workflow and its trade-offs are covered in Runs with Swaps under How To Use. The stored bands then flow into Export like any other solved geometry.
