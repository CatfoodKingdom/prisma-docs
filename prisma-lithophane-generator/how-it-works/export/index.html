Export

Jul 31, 20265 min read

Export is the final stage. By now the generator has solved the image into a stack of filament layers and capped it with white. Export turns that abstract result — a set of per-point height maps, one per material — into a 3D model a slicer such as OrcaSlicer can open and print. Each export produces one chosen output: a set of STL files, or a single 3MF.

From height maps to solid geometry

The solve describes the lithophane as a stack of materials, each with a thickness at every point: a flat white base beneath everything, one map per color filament, and a white cap on top. Export turns these into triangle shells and records whether every object is actually closed and passed its other mesh checks. The base is a simple plate; each color material and the cap rests on whatever lies beneath it, so the running floor rises in the solved print order. That order is real model data — especially for Color Model v2, whose prediction depends on what surrounds each layer — and export preserves it. The physical image footprint comes from the solve-grid dimensions and pitch. A requested border adds a rectangular frame and insets the content within it.

A run with swaps (Runs with Swaps) adds two things. The white fill that tops each filament band up to its flat ceiling becomes real geometry — folded into the same white material as the cap, never a separate filament or file. And the stacking order stops being cosmetic: a mid-print swap is valid only if its band ends at one flat height everywhere, so the material order must match the solved swap plan exactly. Export enforces this — the order is checked against the plan, an audit confirms every band starts at its constant floor and every color stays inside its band, and a mismatch is refused rather than shipped.

Why the meshing must be careful

Naively triangulating a blocky height map produces a mesh that looks closed but is not reliably so. Where two raised regions meet at only a single corner or edge — a pinch contact — a slicer tends to weld the touching points and report a non-manifold solid, which can break slicing.

The generator therefore uses a rectilinear mesher designed for this kind of stepped field. It resolves each shared corner consistently, keeps touch-only contacts from being re-welded into pinches, and closes and orients each material shell before packaging it. When one body still fails a strict welded-mesh check, export can partition it into several same-material bodies. Any remaining failure is reported in the manifest and Mesh Report rather than being silently called watertight.

Field-derived vs exact geometry

How the white cap surface is built is a choice — the Mesh method setting — and it is where the field-derived vs solve-grid distinction lives.

The exact solved raster option builds every material, colors and cap alike, straight from the solve-grid height maps: one mesh cell per solved point. It is faithful to the solve but inherits its blockiness.

The default, field-derived white cap, rebuilds only the white cap from the canonical target upper-surface field on an integer finer grid (2x, 4x by default, 8x, or 16x). This lets the cap surface carry smoother tonal relief than the solve resolution alone would allow — which matters most for the cap’s fine detail (see White Cap) — while the colored geometry stays locked to the solve grid, exactly where the color decisions were made. Both solve modes use the same reconstruction mechanism but supply mode-specific target-policy metadata. Layer by layer, reconstruction fills the space between the color ceiling and target surface and removes sub-printable internal voids and isolated positive-white features.

Only the field-derived route uses the hybrid rigid-guard/freeform cap builder. Exact raster instead uses rectilinear interval bodies and topology partitions on the solve grid. In either route, a banded print’s between-band white fill remains part of the white-cap material; depending on topology, one material may be represented by one or several mesh objects.

STL versus 3MF

Both formats describe the same geometry; they differ in how material is recorded. An STL carries only triangles, with no notion of material, so the STL export writes one file per object — white base, each color material, the cap, the border — into a shared folder, to be loaded together and assigned a filament by hand. A 3MF is a container that can record a material assignment per object: the 3MF export packs every object into one file and tags each with a filament slot, so the model opens with materials already assigned. The assignment is per object, not per print layer — every object is one filament — and objects printed in the same physical material, such as a shared white base and cap, collapse onto a single slot, so the slot count matches the real number of materials loaded. This is what lets a multicolor lithophane open ready to slice.

Alongside the geometry, export writes a manifest recording the content and total dimensions, every object’s material assignment and construction role, and its mesh-quality/build reports.

The swap-banded materials feeding this stage come from Runs with Swaps.
