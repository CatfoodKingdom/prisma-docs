Color-core library

Color-core library

Properties1
tagsgenerator, color

Jul 24, 20265 min read

In one sentence: Prisma/lib/ contains several low-level color, transmission, stack-geometry, registry, and Camera Transform helpers, but their liveness differs substantially—some are central to the current product, some are used only by Calibration, and some are compatibility or reference utilities with no production caller.

This page distinguishes the reusable code from the code that the current Generator and Calibration paths actually call. The modules are mostly framework-free, but they do not form one uniformly live “core.”

Liveness map

lib.stack_geometryPartly liveGenerator appearance prediction, photo-stack prediction, and Calibration fitting

Related architecture nodes: lib.transmission, lib.color, lib.stack_geometry, lib.filaments, and lib.camera_transform.

Two ΔE definitions—and two liveness caveats

The repository contains two non-interchangeable helper functions:

FunctionSpace and formulaLiveness of this exact helper
lib.transmission.deltaE_ok(lab1, lab2)Euclidean distance in OKLabDormant: the product performs equivalent vectorized OKLab distances directly, but has no current caller of this helper
lib.color.compute_dE_from_linear(measured, predicted)Convert linear RGB to CIE Lab, then compute CIE76Dormant copy: Calibration calls the duplicate in calibration/fitting/color_math.py

The underlying metrics are live even though these two exact wrappers are not. Generator solving and palette suggestion compare colors in OKLab. Calibration fitting uses its own CIE-Lab/CIE76 implementation. A numeric value from one space must not be treated as interchangeable with the same number from the other.

Stable source anchors: linear_to_oklab, oklab_to_linear, and deltaE_ok in lib/transmission.py; linear_to_lab and compute_dE_from_linear in lib/color.py; the active Calibration duplicate in calibration/fitting/color_math.py.

OKLab conversion (lib/transmission.py)

FunctionContract
linear_to_oklab(rgb_linear)Vectorized linear-sRGB (..., 3) to OKLab using the hard-coded Ottosson matrices
oklab_to_linear(lab)Vectorized OKLab to linear sRGB; clips the result to [0, 1]
deltaE_ok(lab1, lab2)Scalar Euclidean OKLab distance; currently has no production caller

Because oklab_to_linear clips at the RGB cube, an out-of-gamut OKLab value does not round-trip losslessly. Generator model.to_oklab wraps linear_to_oklab and returns float32.

Calibration fitting carries and calls corresponding implementations in calibration/fitting/color_math.py; it does not import these functions from lib.color.

Spline transmission model (lib/transmission.py)

This is the canonical Generator-side historical spline model. Measured (thickness, T_rgb) knots are interpolated channel-by-channel with monotone PCHIP. Composition multiplies layer transmissions; optional pair corrections can then modify the result.

Build and predict

FunctionContract
build_splineBuilds one PCHIP per RGB channel, requires the first knot at 0.0, disables PCHIP extrapolation, and clips transmission to [0, 1]
predictReturns unity at non-positive thickness, spline interpolation in-range, and _extrapolate beyond the final knot
_get_splinesLazily builds and caches splines in profile['_splines']
_extrapolateExtends the last measured segment with a Beer–Lambert-style log slope

Despite their leading underscores, _get_splines and _extrapolate are part of the practical Generator contract. Current callers include palette/suggest.py, the legacy fixed-color helper in lut.py, and live staged-solver helpers. Calibration has separate fitting-side implementations.

Compose and corrections

compose(layers, corrections=None) multiplies predict(profile, thickness) over an ordered layer sequence and clips the final RGB. When corrections are enabled, it derives the lookup key from the first layer as the overlay and the remaining layers as the base stack:

Thicknesses are formatted to two decimal places. Profiles need a filament_id for a correction to match. _interpolate_correction is anchored to a factor of one at zero thickness and holds the last correction value beyond the measured range.

compute_pair_corrections is not defined here. Calibration produces those artifacts in calibration/fitting/fitter_core.py; Generator loaders consume the published result.

to_srgb(T_linear, gamma=2.2) is a plain gamma-2.2 compatibility helper with no current production caller. Do not confuse it with the exact piecewise sRGB conversion used elsewhere.

Adjacent-layer geometry (lib/stack_geometry.py)

collapse_adjacent_layers merges adjacent runs of the same filament while preserving order. Non-adjacent repeats remain separate. It is live in Generator appearance prediction, the photo-stack predictor, and Calibration physical-stack prediction.

canonicalize_filament_stack zips parallel filament/thickness arrays and applies that collapse; it is live in Calibration fitting. unzip_layers currently has test callers but no production caller.

Filament registry accessor (lib/filaments.py)

load_registry, list_filament_ids, and get_filament are thin, uncached readers over an explicitly supplied registry path. get_filament injects the requested filament_id into the returned record.

These helpers are not the current app catalog boundary: the current whole-repo callers are tests. Generator and Calibration use their application/model-library loaders instead.

Camera Transform artifact (lib/camera_transform.py)

The Camera Transform bridges model-domain RGB and display sRGB:

  • forward F: model RGB to display sRGB through root-polynomial features and monotone channel curves;
  • inverse G: display sRGB to model RGB, baked by Calibration into a 33 × 33 × 33 × 3 LUT and sampled by Generator with trilinear interpolation.

The artifact root uses a CURRENT pointer to select one generation. A generation contains camera_transform.json, inverse_lut_33.npz, and manifest.json. Loaders reject unsafe CURRENT paths, verify manifest hashes, validate schema/shape/finiteness, and cache a single resolved artifact by path plus modification time.

The accepted fit payload uses schema camera_transform_v1, model version v2, 48 finite parameters, ten channel-curve knots, and no lattice. apply_forward evaluates F. invert_forward performs the analytic/Newton inverse during Calibration LUT baking. Generator ingress does not run Newton iteration; it calls load_inverse_lut and apply_inverse_lut.

In packaged-library mode, Generator resolves these artifacts inside the selected immutable published model library. Compatibility data-root fallback remains relevant only outside that mode.
