Preprocessing operators

Preprocessing operators

Properties1
tagsgenerator, preprocessing

Jul 12, 20269 min read

In one sentence: five self-registering image operators (A1, B1, B3, C1, C2) that condition the solve-grid raster before the solve — every one ships off by default — plus two shared helpers, feature_scale (a nozzle-derived spatial anchor) and hue_interp (circular hue interpolation).

Preprocessing operators

These operators live in the preprocessing slot, a chain that runs on the loaded image before the color solve. They are discovered from the filesystem under preprocessing/operators/ (no hand-maintained name list — _discover_preprocessing_operators, pipeline/registry.py:33; the “no hand-maintained tuple” rationale is at pipeline/registry.py:101), self-register via the @register_preprocessing decorator (pipeline/registry.py:123), and each subclasses PreprocessingModule (pipeline/base.py:73).

The slot is executed by run_preprocessing_pipeline (preprocessing/runner.py:210), called once from the live solve path at pipeline/runner.py:1016 — the same run_pipeline that hands off to the staged backend (run_staged_backend_path, pipeline/runner.py:1222–1225). So these operators are live in the webapp solve, not legacy CLI-only code. They run on the post-profile-load raster, before target-cloud computation and the staged solve.

Related: Feature scale anchor · Palette metadata and protect masking · preprocessing slot runner · PreprocessingModule contract · Module management

Class defaults and persisted state

Every operator declares default_enabled = False on its class — that is the fallback when no persisted toggle exists. _get_all_defaults reads the attribute for each registered operator (pipeline/modules.py:34) and load_module_state fills any operator missing from the live toggle file with it (pipeline/modules.py:38). The live enable state lives in app/modules.json, which the module manager rewrites as you toggle operators per-run; it is not a fixed all-off manifest. In the current checkout, c2_soft_gamut_compress is persisted enabled while the other four built-ins are false. Nothing here is guaranteed to be part of a baseline run unless the persisted state enables it.

A1 — bilateral denoise (Wing A)

Edge-preserving denoise of the solve-grid raster via a single OpenCV bilateralFilter.

apply (a1_bilateral_denoise.py:108) runs cv2.bilateralFilter once with d = 2*radius_px + 1 (:123), sigmaColor = sigma_range, sigmaSpace = sigma_spatial (:124-129). It is the simplest operator: no palette, no OKLab — purely spatial sRGB smoothing.

It computes a “flat-region” mask up front (Rec.709 luma, local 5×5 std ≤ 0.02 — a1_bilateral_denoise.py:12-13, :30-32, :119) but uses it only for the reported metrics (flat-patch variance before/after, :141-142); the filter itself is applied globally, not gated by the mask.

B1 — print-scale bilateral (Wing B)

Bilateral flatten whose spatial sigma is tied to the printer’s physical feature scale, not a raw pixel count.

The key difference from A1: B1’s spatial sigma is derived in millimeters from the nozzle, then converted to pixels using the solver’s fine pitch. In _resolve_bilateral_params (b1_printscale_bilateral.py:38): sigma_spatial_mm = feature_scale_multiplier * feature_scale_mm (:44), then sigma_spatial_px = sigma_spatial_mm / solver_fine_pitch_mm (:45), clamped to [0.5, 15.0] px (:15-16, :46-52), and the kernel diameter is 2*round(sigma_spatial_px)+1 (:53). feature_scale_mm comes from resolve_feature_scale_mm(context) (:176) — see feature_scale below; solver_fine_pitch_mm defaults to 0.20 if absent (:177-179).

The filter can run multiple passes (:72-78), then clips to [0, 1] (:79).

ParamDefaultRangeMeaning (:92-135)
feature_scale_multiplier1.00.5–2.0Multiplies the shared nozzle-derived feature scale (2×nozzle). 1.0 = blur exactly at print-feature scale; <1 preserves detail; >1 flattens more.
sigma_range0.050.005–0.25Intensity sigma on [0,1]. Set higher than A1’s because B1 is a flattener, not a denoiser.
passes11–3Bilateral-filter passes; 2–3 strengthen flattening at the cost of edge softness.

Reported metrics include the resolved feature_scale_mm, sigma_spatial_mm/px, kernel_d_px, and flat-region variance before/after (:202-218).

B3 — TV flatten (Wing B)

Total-variation (Chambolle) denoise that drives regions toward piecewise-constant patches, optionally in OKLab.

apply (b3_tv_flatten.py:224) runs denoise_tv_chambolle from scikit-image (:53, called through _tv_denoise). The wrapper reflectively adapts to the installed skimage API (max_num_iter/n_iter_max, channel_axis/multichannel) at :57-65, so it survives version drift.

Weight autoscaling is the Wing-B signature: with weight_autoscale=True, effective_weight = tv_weight * (feature_scale_mm / 0.40) (_effective_weight, :152-166; baseline _AUTOSCALE_BASELINE_MM = 0.40 at :20), then clamped to [0.005, 0.30] (:21-22, :157-159) with a warning if it clamps (:160-165). The 0.40 baseline is the default-nozzle feature scale, so at a 0.2 mm nozzle autoscale is a no-op and the weight you set is the weight applied.

_run_tv (:168) branches on channel_axis: srgb_rgb denoises RGB directly (:176-183); oklab_L_ab converts to OKLab and denoises all three channels (:186-192); oklab_L_only denoises just L and re-attaches the original a/b (:193-200), then converts back to sRGB and clips (:201-205).

Reported metrics are the resolved feature_scale_mm, tv_weight, effective_weight, channel_axis, and n_iter_max (_metrics, :209-222).

C1 — achievable tonemap (Wing C)

Palette-aware tonal compression: remaps source luminance (OKLab L) into the range the chosen filament palette can physically reproduce.

C1 is the first operator that requires palette context (required_context = frozenset({"palette_metadata"}), c1_achievable_tonemap.py:217); it raises ValueError if context.palette_metadata is None (:301-304). The palette supplies the achievable black/white L (:311-312).

How it works: source is converted to OKLab (:307); shadow/highlight anchors are taken as percentiles of source L (:314-317); a 3-anchor PCHIP curve maps [shadow, midpoint, highlight] source L onto [achievable_black, midtone_target, achievable_white] (_build_core_curve, :35-55), where the midtone target is placed via 0.5 ** midtone_contrast (:43). Pixels outside the anchor range are extended by linear tails using the curve’s end slopes (_linear_tail_remap, :58-99), then clamped into the achievable range. The remap is blended with the original L by strength (_tonemap_pass, :156-159), and only the L channel is rewritten — a/b are preserved (:161-162).

ParamDefaultRangeMeaning (:218-259)
strength1.00.0–1.0Blend between source L and the achievable-range remap.
shadow_percentile0.50.0–10.0Source-L percentile treated as the shadow anchor.
highlight_percentile99.590.0–100.0Source-L percentile treated as the highlight anchor.
midtone_contrast1.00.5–2.0Three-anchor PCHIP midpoint placement (0.5**contrast).

The constructor additionally requires shadow_percentile < highlight_percentile, raising otherwise (:281-284). Degenerate guards: C1 returns the input unchanged in two cases — if the achievable range collapses (white <= black + 1e-4, with a degenerate_palette metric, :319-328) or if shadow/highlight L coincide (no degenerate_palette flag, :330-338); both route through _zero_result (:175). C1 declares a preview_key (:211) so it can drive a preview tile. Debug maps: delta_L, clamp_mask (:371-373).

C2 — soft gamut compress (Wing C)

Hue-preserving soft-knee chroma compression: pulls over-saturated pixels in toward the palette’s per-hue maximum chroma without shifting their hue.

Also palette-required (required_context = frozenset({"palette_metadata"}), c2_soft_gamut_compress.py:328). It reads the palette’s chroma envelope from metadata — hue bin centers hue_degrees, lightness bin centers l_bin_centers, and the 2-D max_chroma_by_hue_l bound table (with 1-D max_chroma_by_hue retained as a fallback) (:391-406). For each source pixel it computes OKLab hue + chroma (_hue_and_chroma, :100-105) and queries the chroma bound at that hue and lightness via circular hue interpolation (_query_chroma_bound → interpolate_circular_degrees, :28-96) — see hue_interp.

The soft knee (_run_compression_pass, :147): compression starts at knee_start_ratio * chroma_bound (:153); above the knee, output chroma follows a tanh curve filling the remaining “room” up to the bound (:168-171). The code comment at :166-167 pins this exact tanh form (“Consensus R6 pins this tanh form exactly; do not substitute”). Hue is preserved by scaling a/b uniformly (chroma_scale, :187-203); L is untouched (:205-206).

ParamDefaultRangeMeaning (:329-356)

Degenerate guard: if the palette supplies no hue/chroma samples (or the bound table is mis-shaped or ≈ 0 everywhere) C2 returns identity with degenerate_palette (:409-416, _identity_result at :286). Debug maps: chroma_scale, over_bound_mask (:278-280).

feature_scale — the Wing-B spatial anchor

A single helper that turns the active nozzle diameter into a millimeter “print-feature scale” so B1 and B3 share one definition of “blur at print scale.”

resolve_feature_scale_mm(context, explicit_mm=0.0) (feature_scale.py:45) returns:

  • explicit_mm verbatim if > 0.0 (a per-call override; :65-66);
  • otherwise nozzle_diameter * 2.0 — the constant _FEATURE_WIDTHS_PER_NOZZLE = 2.0 (:37, applied :72-73), encoding the heuristic that a reliably reproduced feature is ~2 bead widths wide;
  • otherwise (missing / non-numeric / non-positive nozzle) the fallback _DEFAULT_FEATURE_SCALE_MM = 0.40 (:42, returned :71, :74).

So at the default 0.2 mm nozzle, feature scale = 0.40 mm (2 × 0.20). Callers are exactly the two Wing-B operators (b1_printscale_bilateral.py:8, b3_tv_flatten.py:14) and the evaluation harness — confirmed via grep. The module header notes printer_min_line_width_mm is deliberately not the anchor (it’s the extrusion floor, ~0.8×nozzle, a different quantity; feature_scale.py:15-17). This 0.40 mm value is also the _AUTOSCALE_BASELINE_MM baseline B3 divides by, which is why autoscale is a no-op at the default nozzle. Detail page: Feature scale anchor.

hue_interp — circular hue lookup

Wrap-aware linear interpolation of a per-hue value array, used by C2 to query the chroma envelope at any OKLab hue angle.

interpolate_circular_degrees(query_degrees, sample_degrees, sample_values) (hue_interp.py:19) linearly interpolates sample_values (indexed by hue bin centers) at arbitrary query hues, wrapping continuously across the 360°→0° seam. Mechanics: queries are normalized mod 360 (:62); a single sample short-circuits to a constant (:64-65); otherwise the sorted bins are wrap-extended by one bin on each side (last −360°, first +360°, :79-80) so a plain np.interp handles the seam without per-query branching (:82). Output is float32, same shape as the query (:82-83). Its only live caller is C2 (c2_soft_gamut_compress.py:13, used at :40) — confirmed via grep; the docstring notes it sits next to feature_scale.py as shared Wing-C infrastructure (:9-10).
