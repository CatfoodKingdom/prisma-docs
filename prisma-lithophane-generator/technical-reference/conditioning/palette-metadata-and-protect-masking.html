Palette metadata

In one sentence: F2 palette metadata samples what colors the chosen filament stack can actually reach — an achievable-color envelope (darkest/lightest points plus a per-hue, per-lightness chroma ceiling) — and hands it to the conditioning operators that compress tone and chroma toward what the print can reproduce.

Note — protect masking was removed. This page previously also documented an F3 protect-subject masking service (preprocessing/protect_mask.py, preprocessing/protect_blend.py, the rembg saliency provider, and brush/raster overrides). That whole subsystem has been deleted: those modules are gone, PreprocessingContext no longer carries a protect mask (preprocessing/types.py:63 holds only palette_metadata), and no operator consumes one. Only F2 survives, and it is what the rest of this page covers.

F2 runs in the generator.pipeline.runner preprocessing slot, before the image is turned into a solve target and before the The staged backend (Stage 0-5) does the actual layer solve. It is an input that conditioning operators (C1, C2) consume — it does not itself edit the image. It is resolved once per solve and passed down through PreprocessingContext.

  • F2 = “what colors can this palette make?” → fed to operators that compress toward the gamut or remap tone.

See also: Preprocessing operators · generator.preprocessing.palette_metadata

How it wires into a solve

F2 is resolved from pipeline/runner.py inside run_pipeline, which the webapp/facade uses. Preprocessing happens in the if config.preprocessors: block (pipeline/runner.py:991) — F2 resolves and the chain runs before the staged backend ever sees the raster.

What it produces (achievable-color envelope)

Source: preprocessing/palette_metadata.py.

resolve_palette_metadata returns a frozen PaletteMetadata (palette_metadata.py:143) with six pinned arrays plus a fingerprint:

FieldShapeMeaning
achievable_black_oklab(3,) float32The darkest OKLab point the stack can reach (lowest L among sampled stacks) — palette_metadata.py:151, palette_metadata.py:556
achievable_white_oklab(3,) float32The lightest reachable OKLab point (highest L) — palette_metadata.py:152, palette_metadata.py:557
max_chroma_by_hue(n_bins,) float32Per-hue-bin maximum reachable chroma — palette_metadata.py:153
hue_degrees(n_bins,) float32Hue-bin centers those chroma caps belong to — palette_metadata.py:154
l_bin_centers(n_l,) float32Lightness-bin centers for the 2D chroma ceiling — palette_metadata.py:155
max_chroma_by_hue_l(n_bins, n_l) float32Per-(hue, lightness) chroma ceiling — palette_metadata.py:156
request_fingerprintstr32-hex digest of the producing request — palette_metadata.py:157

The black/white anchors are C1’s input; the chroma envelopes are C2’s input. Binning uses _HUE_BINS_DEFAULT = 12 (30°-wide) and _L_BINS_DEFAULT = 8 (palette_metadata.py:162-163).

How the envelope is sampled

_candidate_oklab_points (palette_metadata.py:268) builds a cloud of OKLab points by composing transmission stacks within the print budget and projecting each to OKLab via compose + linear_to_oklab from lib/transmission.py (imported palette_metadata.py:50). It is explicitly an envelope sampler, not a full polytope enumeration (palette_metadata.py:287-289).

The coverage strategy (palette_metadata.py:277-282):

  • White sandwich alone — white base + white cap, across the d_wc samples (min / midpoint / max; _d_wc_samples, palette_metadata.py:193-204).
  • Single-filament stacks — each palette color at coarse thickness samples.
  • Pairs (k=2) — every 2-combination, when k_max >= 2.
  • Triples (k=3) — every 3-combination, when k_max >= 3.

Each stack must fit the color budget t_max - d_wb - d_wc (palette_metadata.py:300). The per-layer thickness-sample count is chosen adaptively (_adaptive_samples_per_layer, palette_metadata.py:254-265): the largest value in [_THICKNESS_SAMPLES_MIN=4, _THICKNESS_SAMPLES_MAX=8] (palette_metadata.py:171-172) whose combinatorial candidate count stays within _MAX_CANDIDATE_STACKS = 40_000 (palette_metadata.py:173, counted by _count_candidate_stacks, palette_metadata.py:207). Denser sampling raises each cell’s sampled max toward the true reachable max; the budget cap keeps resolve time bounded.

From that point cloud (resolve_palette_metadata, palette_metadata.py:518):

  • black/white = argmin/argmax of L (palette_metadata.py:555-557).
  • 1D chroma envelope = _chroma_envelope (palette_metadata.py:372) bins points by hue and takes the max chroma per bin, empty bins set to 0 (palette_metadata.py:388-392).
  • 2D hue×lightness ceiling = _chroma_envelope_by_hue_l (palette_metadata.py:486), with empty L-cells interpolated (_fill_chroma_envelope_l_holes, palette_metadata.py:424) and an L-only max dilation applied so queries near a cusp read the peak rather than an averaged-down value (_dilate_l_max_ceiling, palette_metadata.py:455).

If sampling somehow yields no points, the resolver falls back to the bare white-cap point for both anchors and all-zero chroma rather than failing (palette_metadata.py:531-553).

When it runs (opt-in) and how it is keyed

F2 is skipped unless some operator opts in. _chain_needs_palette_metadata (palette_metadata.py:582) returns True only if an operator declares "palette_metadata" in its required_context; otherwise resolve_palette_metadata_for_chain (palette_metadata.py:595) returns None and the chain sees context.palette_metadata = None (palette_metadata.py:608-609). The two opting-in operators are C1 (operators/c1_achievable_tonemap.py:217) and C2 (operators/c2_soft_gamut_compress.py:328) — both frozenset({"palette_metadata"}).

The request is the envelope-relevant slice of PipelineConfig, built by PaletteMetadataRequest.from_config (palette_metadata.py:91). It deliberately includes only fields that move the achievable envelope — palette (sorted, treated as an unordered set; palette_metadata.py:100), the white sandwich identities and thicknesses, t_max, k_max, layer_height, and corrections. It deliberately excludes solver weights like de_threshold / gamut_mode / chroma_weight, image resolution, and preprocessing params (palette_metadata.py:68-72). fingerprint() (palette_metadata.py:113) is a 32-char truncated SHA-256 over the rounded fields (palette_metadata.py:123-138); identical envelopes hash identically. This fingerprint is the palette-change invalidation key.

How C1 and C2 consume it

OperatorUsesBehavior on missing / degenerate
C1 achievable tonemapachievable_black_oklab / achievable_white_oklab L-endpoints to remap tone (c1_achievable_tonemap.py:311-312)raises if metadata is None (c1_achievable_tonemap.py:301-303)
C2 soft gamut compresshue_degrees + max_chroma_by_hue + l_bin_centers + max_chroma_by_hue_l as the per-hue/per-lightness chroma ceiling (c2_soft_gamut_compress.py:391-406)raises if metadata is None (c2_soft_gamut_compress.py:386-388); returns an identity result if the envelope is empty / all-zero

C2 interpolates a per-pixel chroma bound around the hue circle via _query_chroma_bound (c2_soft_gamut_compress.py:28) and soft-knee-compresses chroma toward it. See The Transmission Model for the compose math the envelope sampler builds on and How a Solve Works for where preprocessing sits in the full solve.

Driving it (user-facing)

  • Reach a wider gamut fit / tone fit: enable C1 (achievable tonemap) and/or C2 (soft gamut compress). They self-resolve the F2 envelope; you do not configure F2 directly. Envelope width is determined by your palette, white sandwich, t_max, k_max, layer height, and corrections — those are the only knobs that move it (palette_metadata.py:68-72).

Liveness summary

  • F2 (resolve_palette_metadata_for_chain) — LIVE. Called pipeline/runner.py:997; opted into by C1 (c1_achievable_tonemap.py:217) and C2 (c2_soft_gamut_compress.py:328). Skipped (returns None) when no operator declares palette_metadata.
  • F3 protect masking — REMOVED. The service, blend, rembg provider, and overrides no longer exist; PreprocessingContext carries no protect mask.
