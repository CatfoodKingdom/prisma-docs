Image preprocessing—the F1 slot

In one sentence: F1 runs an ordered chain of enabled image operators after profiles are loaded and before solve-target construction, converting declared color domains at boundaries, validating every returned raster, and optionally publishing view-only previews.

The runner is preprocessing/runner.py; public data types are in preprocessing/types.py; conversions are in preprocessing/color_convert.py. Operator behavior is documented on Preprocessing operators.

Placement in a live solve

pipeline.runner.run_pipeline owns the sequence:

The facade resolves enabled operators from persisted module state and places their instances on PipelineConfig.preprocessors. If the list is empty, run_pipeline skips the whole F1 block and the original raster continues unchanged.

Runner contract

run_preprocessing_pipeline:

  1. sorts instances by (order, fully-qualified class name);
  2. validates that a non-empty chain ends in srgb_u8 or srgb_f32 before any operator runs;
  3. infers ingress as srgb_u8 for uint8 or srgb_f32 for float32;
  4. converts the current raster to each operator’s declared input domain;
  5. calls apply, validates the result, and records a trace step;
  6. collects debug maps under <module_name>:<map_name>;
  7. optionally publishes a display-safe preview without replacing the chain raster.

It returns (postprocess_image, trace, debug_maps). An empty chain returns the original object plus empty trace/debug collections.

Sorting

_sort_operators uses the numeric order first and the fully-qualified class name as a deterministic tie breaker. Filesystem discovery is independently lexical; it does not supply the execution tie order.

The conventional bands are Wing A 100–199, Wing B 200–299, Wing C 300–399, and Wing D 400–499.

Chain and result validation

_validate_chain rejects a last operator whose declared output is not sRGB. This happens before the first apply call, so the chain cannot partially run before that error.

After each call, _validate_apply_result checks:

  • the return value is PreprocessingResult;
  • image is a NumPy array;
  • image height and width match the input;
  • the returned output-domain name is known;
  • dtype matches that returned domain;
  • every output value is finite.

These failures raise PreprocessingContractError and name the offending operator. Operator-specific parameter/context failures may still raise their own exception types—for example, C1/C2 explicitly raise ValueError if required palette metadata is absent.

Each successful PreprocessingTraceStep records module name, input/output domains, a copy of metrics, and cache_hit=False. F1 itself does not cache operator outputs. Trace and debug maps are written to PipelineState; the similarly named preprocessing_metrics field is not populated by this runner.

Color domains and conversion

DomainDtype/rangeMeaning
srgb_u8uint8 [0,255]Display-encoded sRGB
srgb_f32float32, nominally [0,1]Normalized display-encoded sRGB
linear_rgb_f32float32, nominally [0,1]Linear-light sRGB primaries; temporary out-of-range values are allowed
oklab_f32float32D65 OKLab

_convert directly handles the six edges between srgb_f32 and the other three domains. Any other pair is composed through srgb_f32; for example, linear RGB to OKLab becomes linear RGB → sRGB → OKLab.

The sRGB transfer is the IEC 61966-2-1 piecewise function, not Generator’s separate gamma-2.2 PNG approximation. sRGB/linear helpers are sign-preserving and do not clamp. Conversion to srgb_u8 clips and rounds. The OKLab inverse delegates to lib.transmission.oklab_to_linear, which clips to the RGB cube; therefore an OKLab round trip is not an unclipped HDR-preserving path.

The runner owns the initial conversion as well as inter-operator conversions. Operators should not normalize their own input behind the contract.

Context and F2 palette metadata

One frozen PreprocessingContext is built per F1 execution with the current config, an image fingerprint, the original pre-F1 source raster, source_path=None, and optional palette metadata.

resolve_palette_metadata_for_chain runs only if at least one enabled operator declares "palette_metadata" in required_context. If none does, the shared context contains None. If any operator opts in, the single resolved object is present on the shared context passed to every operator; required_context is the opt-in trigger, not a per-operator visibility filter. Palette-blind operators are expected simply not to consume it.

Preview publication

With a snapshot publisher, every successful operator output is converted to srgb_u8 and published as preprocess/<module_name>. That conversion is view-only: the next operator receives the unpreviewed result in its declared domain.

For an operator that declares the palette-metadata requirement, the preview key also incorporates the metadata request fingerprint. This prevents a palette-aware preview from colliding with the same operator’s preview under a different envelope.
