Preprocessing, detail cap, and luminance runtime

Preprocessing, detail cap, and luminance runtime

Properties1
tagsgenerator, preprocessing, luminance, detail-cap, configuration

Jul 27, 20263 min read

Generator has three separate boundaries that are easy to conflate:

  • F1 preprocessing changes the source raster before target construction;
  • the optional luminance handler derives source-driven boundary/detail cap guidance;
  • Stage 4 detail-cap smoothing cleans only the luminance detail-cap map.

They share configuration plumbing but not one enable switch.

F1 module state

Preprocessing operators are discovered from preprocessing/operators/, registered, and executed by run_preprocessing_pipeline. The live solve runs F1 after profile loading and before compute_solve_target_cloud.

All current operator class defaults are off. The server’s live toggle file is <Generator Workspace>/config/modules.json, resolved as data_paths.CONFIG_DIR / "modules.json". If it is absent, load_module_state fills every discovered module from its class default. It also drops retired keys. GET /api/modules, POST /api/modules/toggle, and PUT /api/modules/state expose and persist this state.

preprocessing_params is a separate settings dictionary keyed by module ID. It configures an enabled operator but does not enable one.

Mandatory product normalization

server._force_mandatory_product_settings is used at configuration, profile, solve, and archive boundaries. It:

  • removes retired quiet-drop extras;
  • rounds the minimum cap upward to an integral layer count;
  • forces model-domain ingress;
  • forces printability enforcement and cap-continuity cleanup;
  • forces printable color-region targeting and detail-cap construction;
  • forces the Stage 2 and Stage 4 printability override/gate flags.

detail_cap_enabled is therefore not a current product switch. API/profile/archive validation rejects a persisted false value, and normalization restores true. detail_cap_smoothing_enabled remains separately configurable, but it has an effect only when luminance handling is active.

luminance_mode normalizes to standard or luminance_detail. Applying the luminance-detail preset selects smooth_variable cap mode, enables the handler and detail residual, establishes its conservative defaults, and keeps detail-cap/printability behavior mandatory. Applying the standard preset with reset_standard=True turns the handler off. Retired cap_mode="fixed" is rejected.

Luminance-handler lifecycle

The handler defaults off in both PipelineConfig and SolveConfig. When enabled, run_pipeline configures it twice:

  1. a provisional pre-LUT pass after target construction and white rescaling;
  2. a final pass after target gamut mapping.

That runtime state can constrain effective_boundary_d_wc_max, giving Stage 2 and Stage 4 the same bounded boundary-cap authority.

LuminanceHandler.build_reference samples the configured appearance provider’s white-base/white-cap response, maps target lightness into layer-quantized reference caps, and may include swap-band white fill. build combines that reference with raw solver-implied cap information and returns boundary_cap_request_mm plus detail_cap_reference_mm. Detail guidance is clipped by total-height headroom and the full cap ceiling; it is guidance, not a second color-stack solve.

Provider identity is enforced. If the configuration requests photo_stack_bundle, the handler does not silently substitute the historical spline provider.

Stage 4 detail-cap smoothing

staged.stage4.build_cap_plan computes remaining cap budget from t_max - color_ceiling, resolves boundary and detail requests, and applies cap floors and printability gates.

_apply_stage4_detail_cap_smoothing runs only when all three are true:

  • luminance handling is enabled;
  • detail_cap_enabled is true;
  • detail_cap_smoothing_enabled is true.

Thus standard mode normally bypasses it even though the smoothing setting defaults true. When active, the helper converts detail height to integer layer counts, calls smooth_detail_cap_layers, converts back to millimeters, and clamps to remaining budget and any desired final-cap target.

The smoother removes exact-height speckles and cleans small components/holes in cumulative detail masks. It does not edit color maps, boundary cap, or recipe topology. Its result still passes the Stage 4 printability gates.
