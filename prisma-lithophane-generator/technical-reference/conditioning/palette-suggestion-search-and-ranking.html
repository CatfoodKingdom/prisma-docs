Palette suggestion search and ranking

Palette suggestion search and ranking

Properties1
tagsgenerator, palette

Jul 25, 20264 min read

In one sentence: palette suggestion precomputes nearest distances to single/pair gamut clouds, searches filament subsets exhaustively or by multi-start greedy refinement, enforces distinct alternatives, and—in the normal load-tier workflow—sparsely rescores finalists with three-color gamuts.

Signature and gamut construction are documented on Automatic palette suggestion. This page follows the current generator/palette/suggest.py search contract.

One thorough search path

suggest_palettes has no search_mode. It prepares a _PaletteSearchContext and always calls _thorough_search. Legacy search_mode and quality_weights fields are rejected by the server payload.

_prepare_palette_search_context:

  • filters unsupported/excluded filaments;
  • asserts signature/gamut domain equality;
  • chooses robust ranking for a supplied model backend and mean ranking otherwise;
  • builds/caches single clouds;
  • precomputes one nearest-distance vector per single and pair cloud.

Each trial palette can then be scored by elementwise minima over small arrays rather than by rebuilding gamut clouds and KDTrees.

Exhaustive versus multi-start

_thorough_search computes C(n_available, requested_size):

  • at or below 500,000 combinations, _exhaustive_search evaluates all sets;
  • above 500,000, _multi_start_search uses multiple seeded greedy builds and local swaps.

The exhaustive path scores combinations in chunks of 2,048. It keeps a bounded best-candidate buffer rather than every candidate indefinitely.

The multi-start path ranks individual-filament seeds, uses up to the best eight as starts, greedily adds one filament at a time, then performs up to 20 local-swap passes. If those starts converge to too few distinct sets, it expands scored single-swap neighbors through a frontier until the candidate buffer is sufficiently populated or no new neighbors remain.

Ranking objective

_score_palette_metrics returns:

  • weighted mean distance;
  • maximum distance;
  • weighted percentage above the 0.02 OKLab coverage threshold;
  • weighted 90th percentile.

_palette_rank_score maps those to one scalar:

ModeObjective
meanmean_de
robustmean_de + 0.35·p90_de + 0.15·max_de + 0.03·(pct_above/100)

Robust mode penalizes poorly covered color regions that a mean alone can hide. It is the current photo-stack model path; historical spline suggestion uses mean mode.

The deterministic sort key is rank score, mean, maximum, then sorted filament IDs.

Distinctness and diversity

_select_diverse_candidates never returns a duplicate filament set. It first prefers a set differing from each already-selected set by at least two replaced members (symmetric-difference size at least four). If that preference would return fewer than requested, it fills best-first from rejected but still distinct sets.

The intended product contract is N requested means N distinct palettes when the available/searchable pool permits it. Equality is by filament set, not order or downstream thickness recipe.

Load-tier sweep used by the browser

The browser always sends max_swaps, including zero, so normal use calls suggest_palettes_swap_aware.

For a per-load color capacity P:

  • tier 0 evaluates size P;
  • tier 1 evaluates sizes P+1 … 2P;
  • tier 2 evaluates sizes 2P+1 … 3P;
  • later tiers continue the same pattern, capped by available filaments.

The per-load capacity comes from AMS slots minus reserved white/filler slots. A user request above physical color capacity is capped and reported in per_load_capped.

For each size, the sweep runs _thorough_search. The tier record retains the best candidate for every evaluated size and reports the maximum-size candidate as that tier’s headline coverage. Unless Compute all load tiers is enabled, evaluation stops after a nonzero tier when its maximum-size coverage gain over the previous tier is below improvement_threshold × P. This applies the setting as a required gain per added color across one full additional load.

_recommended_ladder_size then examines the best candidate at every evaluated size. It selects the first size for which no later size gains at least improvement_threshold × added_color_count. Alternatives are drawn from the selected size.

Sparse three-color finalist rescore

suggest_palettes_swap_aware enables three_color_rescore by default. After the single/pair tier search, it selects up to 30 unique finalists in this priority order: current recommendation, tier ladder, then alternatives.

For every triple contained in those finalists, it builds a sparse triple cloud (four color-thickness samples per filament, cap step eight), precomputes centroid distances, and rescales each finalist’s distance vector with the new minima. It then:

  • reranks candidates inside each existing tier;
  • recomputes tier coverage deltas;
  • rebuilds size alternatives;
  • reruns recommendation selection;
  • adds timing/finalist-count provenance.

It does not reopen the exhaustive/multi-start search with triple distances, and it does not evaluate triples for non-finalist palettes. The early-stop decision determines which tiers exist before the rescore; rescoring does not add previously skipped tiers.

If max_swaps is omitted and the direct suggest_palettes branch is used, no triple rescore runs.

Endpoint behavior

The server builds common arguments from the active white sandwich, model exclusions, coverage threshold, target metric weight, and active appearance provider. max_swaps selects between the tier response and the direct candidate response.

Suggestion runs in a background worker with job-qualified status and cancellation. Progress is monotonic at the server boundary; expensive gamut loops check the cancellation callback between units of work.
