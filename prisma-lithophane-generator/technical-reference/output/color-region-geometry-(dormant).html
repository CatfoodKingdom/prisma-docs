Color-region geometry (dormant)

Color-region geometry (dormant)

Properties1
tagsgenerator, geometry

Jul 12, 20266 min read

In one sentence: Prisma/generator/geometry/ turns a solved plan into first-class vector color-region polygons (ColorRegion/RegionGeometry), and mesh/canonical_mesh.py hashes meshes for order-insensitive equivalence — both are real, tested code with no production caller, so they do not feed STL/3MF output today.

This page exists to stop a reader from assuming these two well-built subsystems are on the live print path. They are not. The export path is documented in Exporting Print Files; what is actually wired end-to-end is cataloged in What Actually Runs. This page is the explicit “wired-but-unused” record for the geometry package and the canonical_mesh oracle.

The geometry package — what it does

Prisma/generator/geometry/ derives connected, same-stack color regions from a SolvedMaterialPlan and expresses each as an explicit boundary polygon in solved image-domain millimeters.

ColorRegiongenerator.geometry.regionOne connected same-stack component: exterior ring + hole rings (mm), segment_ids, area_mm2, bbox_mm. frozen dataclass (geometry/region.py:22).

How extract_regions works (developer view)

extract_regions (geometry/extract.py:210) reads three things off the plan and produces region polygons:

  1. It expands the per-segment stack assignment into a full per-pixel stack-label image by indexing segment_stack_id with segment_id_map (geometry/extract.py:229). Those two arrays are the plan’s identity/assignment split — segment identity is immutable, the stack assignment is the mutable material choice (pipeline/solved_material_plan.py:99, pipeline/solved_material_plan.py:100).
  2. For each distinct stack label it runs scipy.ndimage.label (imported geometry/extract.py:18, called geometry/extract.py:239) so that disconnected patches of the same stack become separate ColorRegions — one connected component per region, never fused.
  3. For each component it traces a rectilinear, pixel-corner-aligned boundary by walking mask edges (_mask_to_grid_polygon, geometry/extract.py:38) and unions them with shapely (geometry/extract.py:143), deliberately avoiding marching-squares half-pixel offsets (rationale stated geometry/extract.py:8). The largest ring becomes the exterior and the rest become holes (_extract_rings, geometry/extract.py:153; exterior-vs-hole selection geometry/extract.py:194).
  4. Coordinates are converted to mm using solver_fine_pitch_mm (geometry/extract.py:227) and emitted Y-down in array convention (geometry/region.py:11 documents the convention; the Y flip back to Y-down is applied in _to_y_down, geometry/extract.py:179).

Provenance survives: each region carries the source segment_ids it covers (geometry/extract.py:247, stored at geometry/extract.py:268).

How simplification works

simplify_regions(geometry, tolerance_mm) is the public sweep (geometry/simplify.py:117); it delegates to simplify_region per region (geometry/simplify.py:73), which RDP-simplifies the exterior and each hole ring via the internal _rdp (geometry/simplify.py:25). Contracts worth knowing:

  • tolerance_mm <= 0 is an exact identity — the original objects are returned untouched (geometry/simplify.py:128 for the sweep, geometry/simplify.py:84 per region).
  • Closure is preserved, and a ring that would collapse below 4 vertices is left un-simplified to stay a valid polygon (geometry/simplify.py:67).
  • It is explicitly not printability cleanup — it only re-represents an already-accepted boundary, it never decides whether a region should exist (stated geometry/simplify.py:11). Printability lives elsewhere; see Exporting Print Files.
  • bbox_mm and area_mm2 are recomputed from the simplified rings (geometry/simplify.py:93, geometry/simplify.py:103), reusing _signed_area imported back from the extract module (geometry/simplify.py:101).

Liveness: wired-but-unused

The package is internally complete — geometry/__init__.py re-exports ColorRegion, RegionGeometry, extract_regions, and simplify_regions (geometry/__init__.py:13-geometry/__init__.py:15). But a grep for any importer outside the package itself finds none in Prisma/generator/. The only consumer anywhere in the tree is the test suite:

  • tests/generator/test_phase4_region_extraction.py:16 imports extract_regions, ColorRegion, RegionGeometry and exercises them across ~12 cases (test_phase4_region_extraction.py:62 onward), including an end-to-end run_pipeline → extract_regions case (test_phase4_region_extraction.py:285).

No staged_runner, server, facade, or mesh/export module imports geometry. So despite the package docstring calling these objects the “downstream geometry of record for color-layer export” (geometry/__init__.py:4), nothing exports through them — that header is aspirational, not a description of the current wiring. Trust the line anchors above, not the prose at the top of the file. This matches the audit note in Staged artifacts and the SolvedMaterialPlan contract and the dormancy entry in What Actually Runs.

Do not confuse with the live export geometry

The STL/3MF that OrcaSlicer opens is built by the mesh/export path described in Exporting Print Files, driven from the staged backend (The staged backend (Stage 0-5)). The shapely.geometry imports in mesh/rectilinear_interval.py and mesh/printability.py are unrelated to this geometry package — same word, different code. The historical plans that wanted region geometry to become the export authority (e.g. the 2026-04-11 “geometry-native printability” sketches) were never wired in.

Status — geometry package: WIRED-BUT-UNUSED (test-covered, no production caller). Confirmed by grep over Prisma/generator excluding the package and the test that imports it.

canonical_mesh — a test/verification equivalence oracle

mesh/canonical_mesh.py answers one question: “are these two meshes the same shape, ignoring face order, vertex order within a face, and vertex renumbering?” It is a verification helper, not part of building geometry.

FunctionAnchorBehavior
canonical_triangle_arraymesh/canonical_mesh.py:43Quantize each triangle (XY at mesh pitch, Z at layer height — _quantize_triangles, mesh/canonical_mesh.py:30), sort the 3 vertices within each triangle (mesh/canonical_mesh.py:67), then sort triangles lexicographically (mesh/canonical_mesh.py:72).
canonical_mesh_hashmesh/canonical_mesh.py:76SHA-256 over that array, domain-separated by the quanta and face count (mesh/canonical_mesh.py:101-mesh/canonical_mesh.py:108). Accepts (vertices, faces) arrays or a trimesh.Trimesh (mesh/canonical_mesh.py:87).
canonical_mesh_equalmesh/canonical_mesh.py:112True iff two (vertices, faces) meshes hash equal.

The criterion is spelled out at mesh/canonical_mesh.py:10-mesh/canonical_mesh.py:19: intentionally insensitive to face/vertex ordering and index renaming, while still catching any real geometric difference. It exists so an emitter rewrite that reorders faces can be proven output-preserving even when byte-identical STL is no longer available (mesh/canonical_mesh.py:6).

Liveness: suspected inert on the live path

Grep across the whole tree finds these symbols referenced only in: this file, the Architecture node generator.mesh.canonical_mesh, two docs/mesh_printability/ plan/validation write-ups, the doc agent’s knowledge files, and exactly one runnable caller — scripts/benchmark_mesh_export_heavy_options.py:23 imports canonical_mesh_hash and calls it at scripts/benchmark_mesh_export_heavy_options.py:123 to fingerprint exported objects in a benchmark. No Prisma/generator/ source path calls it on a live export, and (unlike the geometry package) no test in tests/ imports it — a grep for canonical_mesh under tests/ returns nothing.

Status — canonical_mesh: SUSPECTED INERT on the live path. Its sole non-doc caller is the standalone benchmark script scripts/benchmark_mesh_export_heavy_options.py; it was the equivalence oracle for the white-cap vectorised-emitter work (docs/mesh_printability/validation/white_cap_step3_vectorised_emitter_2026-04-20.md) and survives as a reusable check, not as a runtime gate.

If you want to revive either

  • To put region geometry on the export path you would add a caller that takes state.solved_plan (The pipeline orchestrator and shared state), runs extract_regions, optionally simplify_regions, and feeds the polygons to an emitter — none of that wiring exists today.
  • To use canonical_mesh as a CI gate, import canonical_mesh_hash/canonical_mesh_equal in a test and assert two emitter variants agree; the benchmark script (scripts/benchmark_mesh_export_heavy_options.py) shows the call shape.
