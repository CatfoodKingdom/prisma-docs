From solve to mesh the export pipeline

From solve to mesh the export pipeline

Properties1
tagsgenerator, export

Jul 14, 202612 min read

In one sentence: export_solve_bundle reads a materialized solve bundle off disk, decides whether to print the exact solved raster or a smoother field-derived white cap, builds one watertight mesh object per material into a single ExportMeshBundle, and serializes it as per-object STL files or one packed 3MF — writing an export_manifest.json that records every object’s geometry, material, and mesh quality.

This page is the backend mechanics of export. For the user-facing webapp flow (HTTP routes, polling, AMS swap plan) read Exporting Print Files; this page follows what happens inside the one entry point that page calls. The whole contract lives in generator.mesh.post_solve_export and is deliberately free of any FastAPI/UI dependency — geometry is built before serialization, and format writers only serialize already-built meshes (mesh/export_mesh_bundle.py:1).

The boundary: MeshObject and ExportMeshBundle

Everything funnels through two frozen dataclasses in generator.mesh.export_mesh_bundle. They are the export boundary: mesh generation happens before them, format writers only consume them.

A MeshObject (export_mesh_bundle.py:16) is one positioned mesh in the shared coordinate frame. It carries raw vertices/faces arrays plus four identity strings — object_key, material_key, role, mesh_style — an optional 4×4 transform, and free-form metadata. It is built from a trimesh via MeshObject.from_trimesh (export_mesh_bundle.py:29), which copies vertices as float64 and faces as int64. to_trimesh (export_mesh_bundle.py:55) reconstructs a trimesh.Trimesh with process=False and applies the stored transform lazily, so the transform is only baked at serialization time.

MeshObject fieldMeaning
object_keyUnique handle; also the STL filename stem and a thickness-map lookup key
material_keyWhich filament the object prints in (drives 3MF extruder slot)
roleSemantic tag (white_base, color, combined_white_cap, white_cap_slab, …) used for display names
mesh_styleHow it was built (flat_plate, rectilinear_interval, primitive_frame, hybrid styles)
transformOptional 4×4; None until a border shift or hybrid placement applies one

An ExportMeshBundle (export_mesh_bundle.py:73) holds the tuple of MeshObjects plus the export-wide metadata: image_domain_width_mm/height_mm, layer_height_mm, xy_quantum_mm, the object_coordinate_frame string, a mesh_build_report, a per-object quality map, color_export_details, and source_blueprint_fingerprint. The frame string is the constant OBJECT_COORDINATE_FRAME = "x-left-to-right_y-bottom-to-top_z-build-plate-mm" (post_solve_export.py:63). object_by_key (export_mesh_bundle.py:90) is a linear lookup over the tuple.

Note the bundle is immutable: every transformation (_with_mesh_build_report at post_solve_export.py:1138, _with_export_border at post_solve_export.py:1185) constructs a new ExportMeshBundle rather than mutating one.

The ten-stage pipeline

export_solve_bundle (post_solve_export.py:2549) is the integration entry point. The webapp calls it from _perform_export_files (server.py:5813, at the call site server.py:5884); the heavy-benchmark harness and the export tests call the same function. It walks a fixed ten-stage progress sequence, DEFAULT_EXPORT_STAGES (post_solve_export.py:199), emitting an ExportProgressEvent per stage and timing each scope with an ExportTimingCollector (post_solve_export.py:167).

#Stage idWhat happens in export_solve_bundle
1load_bundleResolve the bundle dir, load arrays.npz and the JSON sidecars (post_solve_export.py:2583)
2detect_solve_modeDetect standard vs luminance; pull pitch / layer height / base thickness / border from metadata (post_solve_export.py:2591)
3prepare_material_mapsCopy color maps, build the RectilinearExportConfig (post_solve_export.py:2651)
4build_geometry_sourceBranch on exact-raster vs field-derived (post_solve_export.py:2686)
5build_color_base_meshesWhite base flat plate + one z-slab object per color filament
6build_white_cap_meshesExact white cap (with topology fallbacks) or hybrid field cap
7validate_banded_geometryFor swap-banded plans, audit band geometry via audit_banded_export_geometry (post_solve_export.py:2769); no-op otherwise
8serialize_outputsWrite per-object STLs (3MF packing is done by the caller afterward)
9validate_meshesOptional reload-and-recheck of written STLs
10write_manifestBuild and write export_manifest.json

Web publication is a directory transaction

export_solve_bundle writes to the directory its caller supplies. The web server never supplies the final user-facing directory directly: _perform_export_files creates a private .export-stage-{export_id}-{nonce} sibling under OUTPUT_DIR and sends every STL, 3MF, manifest, and swap-instruction write there. _finalize_staged_export computes the response against final paths, rewrites absolute staging paths in the manifest to their final equivalents, and issues a final publish_outputs progress event. That event is the last cooperative cancellation checkpoint.

Only after every deliverable, manifest update, size check, and response record succeeds does the server rename the complete staging directory to {export_id}. The destination must still be absent; an independently created directory is never replaced. Failure or cancellation before that rename recursively removes the private stage and leaves no user-visible partial export. No fallible export work occurs after the rename. Download and individual-file GET routes resolve requested directories without creating missing ones.

Stage 1 — Load the bundle

_resolve_solve_bundle_dir (post_solve_export.py:2279) accepts either an arrays.npz file, the directory containing it, or a parent that holds exactly one such directory; it raises FileNotFoundError if it cannot find a unique one. _load_bundle_arrays (post_solve_export.py:2295) loads arrays.npz with allow_pickle=False. Three JSON sidecars are read with _load_json_file (post_solve_export.py:2269): stageA_field_bundle_summary.json (the summary), prediction_replay_metadata.json (the replay, which names the color filament ids), and run metadata via _bundle_run_metadata (post_solve_export.py:2303, preferring run_template.json then run.json). The webapp writes all of these in _materialize_post_solve_export_bundle_from_cached_solve before calling export — the replay block records color_thickness_filament_ids (server.py:4724).

Stage 2 — Detect the solve mode

detect_solve_mode_from_metadata (post_solve_export.py:266) returns a SolveMode enum — STANDARD or LUMINANCE (post_solve_export.py:74). Solve mode is not a user export toggle; it is detected. The signal is a required luminance_mode key, searched across run/bundle metadata and their nested export_metadata physical_geometry / white_cap_field_target sections (post_solve_export.py:300); standard maps to STANDARD, any other value to LUMINANCE. If no luminance_mode is present anywhere it raises ExportPreparationError (post_solve_export.py:305) — the old array-key fallback is gone, and array_keys is now ignored (post_solve_export.py:274). This stage also reads pitch, layer height, and white-base thickness from the solved bundle’s physical_geometry metadata via _required_physical_float (post_solve_export.py:2363, sourced by _physical_geometry_metadata_from_run at post_solve_export.py:2343); border settings come from _first_config_float (post_solve_export.py:2382) / _first_config_bool (post_solve_export.py:2408), which search a priority chain of metadata containers. If border is disabled, both border dimensions are forced to zero (post_solve_export.py:2646).

Stage 3 — Prepare material maps (now a near no-op)

_bundle_color_maps (post_solve_export.py:2450) unpacks the (F, H, W) color_thickness_maps array into a {filament_id: 2D map} dict keyed by the replay’s color_thickness_filament_ids, raising if the count mismatches (post_solve_export.py:2464). A RectilinearExportConfig (post_solve_export.py:214) is assembled from the resolved dimensions; its export_policy() (post_solve_export.py:232) produces a GeometryExportPolicy (generator.mesh.geometry_policy, geometry_policy.py:96) carrying the canonical printability pitch.

The separate module prepare_export_material_maps (generator.mesh.material_maps, material_maps.py:9) is the historical “prepare material maps” step but is now intentionally a near no-op: it returns shallow copies of the maps and ordering unchanged (material_maps.py:19). Its docstring confirms it previously promoted a solve-only translucent-underfill placeholder into a real filament map, but that feature was removed (material_maps.py:15). Liveness: this function is still wired — the webapp calls it through _prepare_export_materialization (server.py:805 → server.py:811), which runs before the bundle is materialized, not inside export_solve_bundle. So in the webapp path the maps are prepared (copied) once on the server side and the in-bundle “prepare_material_maps” stage just rebuilds the config. The two are distinct steps that happen to share a stage name.

Stage 4 — Choose the geometry source

GeometrySource (post_solve_export.py:67) is the one genuinely user-visible export choice: FIELD_DERIVED or EXACT_RASTER, normalized by normalize_geometry_source (post_solve_export.py:246). The branch is at post_solve_export.py:2686.

  • Exact raster loads the combined white-cap thickness map from the bundle via _bundle_white_cap_map (post_solve_export.py:2474) and calls build_exact_raster_mesh_bundle (post_solve_export.py:1535).
  • Field derived reconstructs the white-cap height field from the bundle arrays via reconstruct_field_white_cap_from_arrays (generator.mesh.field_white_reconstruction) (post_solve_export.py:2710). It validates the field is an integer uniform upscale of the solve grid (post_solve_export.py:2725), derives field_scale, builds a finer-pitch RectilinearExportConfig and a HybridWhiteCapConfig, and calls build_field_derived_mesh_bundle_mixed_resolution (post_solve_export.py:2748).

Stages 5–6 — Build the geometry

Both geometry sources share _base_and_color_objects (post_solve_export.py:1298) for the base and color stacks:

  • The white base is a single flat plate via generate_flat_plate (post_solve_export.py:1319), object key __white_base__ (post_solve_export.py:55), role white_base, style flat_plate.
  • Each color filament is meshed as a rectilinear interval body that floats on the accumulating floor (the running sum of layers below it) via _mesh_rectilinear_interval (post_solve_export.py:472, delegating to generator.mesh.rectilinear_interval mesh_interval_map). Color order follows the ordering, skipping any __-prefixed keys (post_solve_export.py:1333).
  • If a color body fails the strict reload-quality check, it is rebuilt defensively — first as a same-material topology quarantine (_build_color_quarantine_parts, post_solve_export.py:1109), and if that still fails as constant-Z slab bodies (_build_color_z_slab_parts, post_solve_export.py:992). This exists because a clean single-body mesh can become non-manifold after STL vertex welding; splitting at snapped plateaus keeps geometry exact while avoiding reload pinches (post_solve_export.py:1006).

The white cap differs by source:

  • Exact raster (build_exact_raster_mesh_bundle, post_solve_export.py:1535) meshes the combined cap as one rectilinear interval (post_solve_export.py:1566). If it passes strict quality it ships as a single combined_white_cap object (post_solve_export.py:1597). If not, it falls through a cascade: forced slabs (_build_exact_white_cap_slabs, post_solve_export.py:506), then a topology quarantine (_build_white_cap_quarantine_parts, post_solve_export.py:781), then a recursive adaptive Z-partition that splits only failing Z ranges (_build_exact_white_cap_adaptive_parts, post_solve_export.py:602). Each branch records its selected_strategy.
  • Field derived (build_field_derived_mesh_bundle_mixed_resolution, post_solve_export.py:1987) keeps color stacks and base on the exact solve grid, nearest-upsamples only the combined color-top witness map to the field resolution (post_solve_export.py:2080), then builds a hybrid guard/freeform white cap via build_overlap_white_cap_mesh (generator.mesh.hybrid_white_cap) (post_solve_export.py:2081). It asserts the color/field/hybrid configs agree on solve pitch, layer height, and base thickness (post_solve_export.py:2036).

Both builders finish through _bundle_from_objects (post_solve_export.py:2138), which stamps the mesh_build_report with geometry source, detected solve mode, geometry policy, and per-object vertex/face totals, then optionally wraps the bundle with a printable border frame via _with_export_border (post_solve_export.py:1185). When a border is enabled, the content objects are translated inward by the border width and a __border__ frame object (post_solve_export.py:62) is appended, printed in the white-cap material (post_solve_export.py:1254).

Stage 7 — Audit swap-banded geometry

For swap-banded plans only, export_solve_bundle audits the banded geometry with audit_banded_export_geometry, folds the result into the mesh_build_report and manifest validation block, and raises ExportPreparationError if the audit fails. The audit checks the stored band plan against the emitted color floors/ceilings, pause planes, and total non-border surface. Exact-raster export derives the expected surface from the solve-grid cap map; field-derived export deliberately substitutes the maximum of the reconstructed field-resolution cap actually used to build the mesh (post_solve_export.py:2696-2737, :2783-:2797). This prevents a valid field-derived swap export from being rejected against the different solve-grid cap maximum while preserving all band/pause checks. It does not write a duplicate standalone audit JSON. When there is no band plan the stage is a no-op. The banded solve/plan story itself lives in AMS grouping and swap planning.

Stage 8 — Serialize per-object STL (3MF is the caller’s job)

If write_stls is true, export_solve_bundle imports and calls write_export_mesh_bundle_as_stls (generator.mesh.export_serializers, export_serializers.py:90) into an stls/ subdirectory (post_solve_export.py:2808). That writer skips empty objects, maps each object_key to a filename via _object_filename (export_serializers.py:20), and bakes the transform by exporting obj.to_trimesh(copy_arrays=False) (export_serializers.py:105). It returns {object_key: Path}.

The 3MF path is not inside export_solve_bundle. When the user picks 3MF the webapp passes output_format == "3mf", so export_solve_bundle is called with write_stls=(output_format == "stls") — i.e. False for 3MF (server.py:5889) — and the caller packs the in-memory bundle with write_export_mesh_bundle_as_3mf (export_serializers.py:373) afterward (server.py:5929). That writer builds one OPC-packaged zip: a [Content_Types].xml, a _rels/.rels, and 3D/3dmodel.model (export_serializers.py:413). Each object becomes a <object> with a slic3rpe:extruder slot (export_serializers.py:134) and an identity-transform <build> item; transforms are baked into vertices before writing (export_serializers.py:129). The extruder slot per object comes from filament_assignments — the webapp builds these by assigning one slot per distinct filament id via _filament_assignments_for_export (server.py:4768), and human-readable names via _material_display_names_for_export (server.py:4751), passed at server.py:5934–5935. Liveness: both STL and 3MF writers are live — STL via export_solve_bundle, 3MF via the webapp 3MF branch and the dedicated test tests/generator/test_export_3mf_filename.py.

Stage 9 — Validate quality

Mesh quality is computed at build time per object with check_mesh_quality (generator.mesh.quality, quality.py:20), which reports watertightness, open edges, pinch edges (counts != 2), and winding consistency. The export uses two stricter local gates: _quality_passes (post_solve_export.py:344, requires watertight + zero open + zero pinch) and _strict_processed_quality (post_solve_export.py:352), which re-welds the mesh with process=True and counts non-2-valence edges — emulating what a slicer-reload would see. This stage itself is optional reload validation: only if validate_written_meshes is true does it re-load every written STL from disk through _reload_quality_for_path (post_solve_export.py:2525) and record reload_quality (post_solve_export.py:2815); otherwise it is disabled by default (post_solve_export.py:2823). In the webapp this is driven by payload.validate_written_meshes (server.py:5890).

Stage 10 — Write the manifest

build_export_manifest (post_solve_export.py:2187) assembles the JSON-serializable manifest (schema post-solve-export-manifest-v1, post_solve_export.py:2208). Its status is "ready" unless any object’s quality shows open edges, pinch edges, or non-watertightness, in which case "mesh_quality_failed" (post_solve_export.py:2211). It records the content/export footprint, border, grid, geometry policy, a per-object list (with STL paths if written), the full quality map, and the mesh_build_report. _jsonable (post_solve_export.py:310) coerces enums, numpy scalars/arrays, and Paths. write_export_manifest (post_solve_export.py:2262) writes it pretty-printed and sorted to export_manifest.json. The performance timings dict (ExportTimingCollector.as_dict, post_solve_export.py:191) is attached before writing (post_solve_export.py:2856).

The white-cap field-target contract

The field-derived path and solve-mode detection are governed by generator.white_cap_contract (white_cap_contract.py), a dependency-free module of shared export-contract constants that post_solve_export imports directly. It fixes the canonical field-target array key white_cap_field_target_upper_surface_map and metadata key white_cap_field_target (white_cap_contract.py:7-10) under schema white-cap-field-target-v1, alongside the physical_geometry metadata key that carries pitch / layer height / base thickness. detect_solve_mode_from_metadata and _field_target_metadata_from_run read these keys; a field-derived export is rejected unless the run metadata names this exact field target (post_solve_export.py:2336). The module also enumerates the three per-mode white-cap policies (white_cap_contract.py:12-16) — POLICY_STANDARD_SMOOTH_VARIABLE_CANONICAL, POLICY_STANDARD_APPEARANCE_BOUNDED_STRUCTURAL_SPLIT, and POLICY_LUMINANCE_DETAIL_CANONICAL — and exposes quantized_cover_floor_mm (white_cap_contract.py:19), the smallest layer-quantized cap thickness at or above a minimum cover.

What you get back

export_solve_bundle returns a PostSolveBundleExportResult (post_solve_export.py:86): the in-memory bundle, the manifest dict and its written manifest_path, the output_paths map ({object_key: Path} for written STLs), the tuple of progress_events, and reload_quality. The webapp reuses result.bundle directly to pack the 3MF, so the meshes are never re-read from disk for that format.

Progress and timing plumbing

ExportProgressReporter (post_solve_export.py:126) emits an ExportProgressEvent (post_solve_export.py:101) per stage; the webapp adapts these to its polling shape in _progress_dict_from_export_event (server.py:5754), turning stage index + fraction into an overall percentage. ExportTimingCollector.scope (post_solve_export.py:175) is a context manager that records wall-clock per labeled stage for performance audits, surfaced under manifest["performance"].
