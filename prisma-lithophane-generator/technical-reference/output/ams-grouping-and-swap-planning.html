AMS grouping and swap planning

AMS grouping and swap planning

Properties1
tagsgenerator, grouping

Jul 14, 20267 min read

In one sentence: when the solved palette needs more color filaments than fit in one AMS load, the generator runs a two-pass banded solve — a scout pass measures color usage, a deterministic planner partitions the palette into consecutive fixed-height swap bands, each band’s leftover height is topped up with white, and export emits per-band AMS slot tables plus OrcaSlicer M600 pauses at each band boundary.

This page covers everything that happens when the palette is too big for a single AMS. It serves both the user driving the wizard and the developer tracing how the band planner, the persisted swap_grouping block, and the export instruction writer fit together.

This replaced the old pluggable grouping. The former GreedyGrouping / GroupBudgetGrouping modules (grouping/greedy_optimize.py, grouping/beam_search.py) and the swap.optimize_grouping / plan_filament_groups / reconcile_export_groups machinery have been deleted. grouping/ now holds only band_plan.py and banded_export.py, and grouping is an automatic banded solve, not a post-solve module the facade wires. Do not confuse this with the offline Fixed-budget layer scheduling (experimental) scheduler, which is unrelated.

The slot budget

A printer has a fixed number of AMS slots. Some are reserved for white; the rest hold color. The budget is computed on the solve config:

  • ams_slots (default 4) and white_slots (default 1) — pipeline/state.py:90, pipeline/state.py:91.
  • effective_white_slots() bumps the white reservation to 2 when the white base and white cap are different filaments (they need two physical slots), otherwise keeps white_slots — pipeline/state.py:214-217.
  • color_slots() = ams_slots - effective_white_slots() — pipeline/state.py:219-220.

So with the default 4-slot / single-white setup you get 3 color slots. Pick a white cap filament that differs from the base and you drop to 2 color slots (one extra slot is spent on the second white). The same accessors exist on the facade SolveConfig (facade.py:200-206) and are read through config in the runner.

When banding triggers

Banding runs only when the palette overflows one load. _swap_banding_requested (pipeline/runner.py:50-55) returns true only when all three hold:

  1. the preset is "full" (preview/compare never band),
  2. this is not itself a scout sub-solve (_swap_banding_scout is not set), and
  3. len(config.palette) > config.color_slots().

If everything fits in one load, none of this page happens — the run exports as a single group with no swaps. There is also a hard ceiling: swap-band planning stops at MAX_EXHAUSTIVE_FILAMENTS = 10 colors (grouping/band_plan.py:13); a larger palette raises before any solve (pipeline/runner.py:894-898, grouping/band_plan.py:165-168).

The two-pass banded solve

When banding is requested, run_pipeline does a scout → plan → solve sequence (generator.pipeline.runner):

  1. Scout — _run_swap_banding_scout (pipeline/runner.py:84) runs the ordinary unbanded pipeline at bounded resolution (_downsample_swap_scout_image, pipeline/runner.py:69) with _swap_banding_scout=True so it does not recurse into banding. Its thickness maps are the measurement of how much of each color the image actually uses.
  2. Plan — choose_band_plan (grouping/band_plan.py:149, called pipeline/runner.py:940) partitions the palette from those scout maps (below).
  3. Store — the plan is serialized onto the state: state.swap_grouping = _swap_grouping_metadata(...) (pipeline/runner.py:947).
  4. Solve — the real solve then runs with the band structure fixed. The remaining height above the color bands is reserved for the white cap: cap_limit_mm = t_max - d_wb - sum(band_layers)·layer_height (pipeline/runner.py:953–957), stored on the block (pipeline/runner.py:959) and applied by the staged backend to cap d_wc_max (_banded_luminance_cap_limit_mm, pipeline/staged_runner.py:9273–9277) so total Z stays within t_max.

The band plan — choose_band_plan

choose_band_plan (grouping/band_plan.py:149) receives the palette already in canonical dark-first order and keeps that order within and across bands, including filaments the scout never used:

  • Group count = ceil(len(palette) / color_slots) (grouping/band_plan.py:181).
  • Candidate partitions — _canonical_partitions (grouping/band_plan.py:40) enumerates each constrained partition of the ordered palette into that many groups of at most color_slots filaments, once each, in canonical order.
  • Band height — for each group, the band’s height in layers is ceil of the 0.99 quantile (BAND_HEIGHT_QUANTILE, grouping/band_plan.py:12) of that group’s summed per-pixel thickness over active pixels, floored at one layer (_height_layers, grouping/band_plan.py:83-86). The active mask is total color thickness > 1e-9 (grouping/band_plan.py:189).
  • Objective — the partition minimizing (total band layers, predicted white-fill volume, canonical key) wins (grouping/band_plan.py:216, grouping/band_plan.py:223): fewest layers of print height first, least wasted white second, a deterministic tiebreak third.
  • Budget clamp — if the winning plan’s total band layers exceed the color budget (effective_max_layers()), _clamp_band_layers scales each band down proportionally (grouping/band_plan.py:89-96); it raises if the budget cannot give every band at least one layer (grouping/band_plan.py:92-93).

The result is a frozen BandPlan (grouping/band_plan.py:28) carrying groups, band_layers, unclamped_band_layers, per-group usage stats, and the clamped flag.

Per-band white fill — band_fill_maps

Because each band is a fixed committed height, any pixel whose color stack is shorter than its band height is topped up with white. band_fill_maps (grouping/band_plan.py:119) computes, per band, fill = band_layers·layer_height − sum(group color thickness), clamped to >= 0 (grouping/band_plan.py:137-140); it raises if any pixel’s color exceeds its assigned band height (grouping/band_plan.py:138-139). This white fill is what makes every band exactly its planned height regardless of local color, so the swap-band boundaries sit at constant Z across the whole print. The facade calls band_fill_maps when reconstructing preview/solve images (facade.py:334, facade.py:367, facade.py:717, facade.py:753); the staged backend uses it for the actual fill geometry.

The persisted swap_grouping block

_swap_grouping_metadata (pipeline/runner.py:130) turns the BandPlan into a JSON-serializable dict (version = "swap_banding_v1") that is the single source of truth for export — nothing downstream re-derives band boundaries from the solved thickness maps. Its keys:

groupslist of filament-id lists, one per band (canonical order)

pause_z_mmZ of each band boundary: d_wb + cumulative_layers · layer_height (pipeline/runner.py:131-135)
canonical_palettethe dark-first order the plan was built on
layer_height_mm, d_wb_mm, quantilereconstruction constants
per_group_scout_usage, scout_resolution, clamped, predicted_fill_volume_mm_pxdiagnostics

Export-time swap planning

Group geometry and swap instructions are produced at export time from the persisted block. The endpoint is GET /api/export/swap-instructions → get_swap_instructions (server.py:6397), which delegates to _build_swap_instruction_payload (server.py:6291). Sequence:

  1. Read AMS capacity from current config, not the cached solve — ams_slots/white_slots come from _cfg() because the user may have changed printers after solving (server.py:6303-server.py:6305).
  2. Parse the persisted block — _swap_grouping_from_solve (server.py:1290) feeds banded_export_plan_from_metadata (grouping/banded_export.py:51, called server.py:6320), which validates the JSON into a frozen BandedExportPlan (grouping/banded_export.py:22). It returns None for an unbanded run; a partially populated block is a hard error (grouping/banded_export.py:60-62), because guessing a band boundary could put a color below the wrong pause.
  3. Assign fixed color slots — band_slot_tables (grouping/banded_export.py:159, called server.py:6336) maps each band’s filaments to color slots 1..N and never swaps white; it raises if a band’s group exceeds the active printer’s color-slot capacity (grouping/banded_export.py:166-167).
  4. Generate instructions — generate_swap_instructions (swap.py:16, called server.py:6343).
  5. Generate pause G-code — generate_orcaslicer_pause_gcode (swap.py:49, called server.py:6383).

The banded payload returns banded: True with per-band groups (z_start/z_end from BandedExportPlan.band_floor_mm / band_ceiling_mm), pause_z_mm, instructions, and gcode. For an unbanded run (the palette fit one load, so there is no band plan), export falls back to _build_static_swap_instruction_payload (server.py:6193): banded: False, a single group, no pauses, and "; No filament swaps needed".

Instruction text and M600

generate_swap_instructions renders through _generate_banded_swap_instructions (swap.py:84): print dimensions, total height, per-band AMS slot assignments, one SWAP block per band boundary, then a white-cap section. Total lithophane height is final_color_ceiling_mm + max(wc_map) so the tallest color/fill stack and the thickest local cap need not coincide (swap.py:117). The number of mid-print swaps is len(pause_z_mm) (swap.py:119). Each swap’s height is the band boundary’s pause_z, converted to an approximate layer via max(1, round(pause_z / layer_height)) (swap.py:160), and the block diffs the two bands’ slot tables so the user sees exactly which color slot to unload/load. White slots are declared fixed for the whole print (_fixed_white_slot_lines, swap.py:55); a distinct white-cap filament requires two dedicated white slots (swap.py:103-106).

The actual pause command is M600. _generate_banded_orcaslicer_pause_gcode (swap.py:189) emits M600 ; pause for filament change at each band boundary (swap.py:201); with no boundaries it returns "; No filament swaps needed" (swap.py:192-193).
