AMS grouping and swap planning

AMS grouping and swap planning

Properties1
tagsgenerator, grouping

Jul 16, 20266 min read

In one sentence: when a full solve has more color filaments than the selected printer can hold at once, Generator scouts actual use, chooses fixed-height Z bands and filament groups, constrains the final solve to that immutable plan, adds white fill to complete every band, and later renders slot changes plus OrcaSlicer M600 pauses from the persisted plan.

Swap banding is part of the solve, not an export-time optimization. Export validates and renders the plan that the solve already committed; it must not infer new band boundaries from thickness maps.

Slot capacity

PipelineConfig starts with four AMS slots and one white slot. The effective reservation depends on the chosen white filaments:

  • when base white and cap white are the same, effective_white_slots() returns the configured white-slot count;
  • when they differ, it reserves at least two white slots; and
  • color_slots() is total AMS slots minus the effective white reservation.

With the default four-slot, single-white configuration, three slots remain for color. A distinct cap white normally reduces that to two.

Trigger and supported scope

_swap_banding_requested is true only when:

  1. the facade preset is full;
  2. the run is not itself the internal scout; and
  3. the canonical palette contains more filaments than color_slots().

Preview solves do not enter this route. An ordinary full solve whose palette fits uses no band metadata and needs no mid-print swap.

The exhaustive planner accepts at most ten color filaments. Overflowing that limit raises before the final solve. The current banded route supports both the historical spline and Photo Stack appearance providers; other provider kinds are rejected explicitly.

Scout, plan, final solve

The live sequence in pipeline.runner.run_pipeline is:

  1. Scout: rerun the full pipeline with _swap_banding_scout=True, using a copy of the source limited to a 384-pixel long side. This prevents recursive banding while preserving the main solve’s source raster.
  2. Measure: collect one scout thickness map for every palette filament, substituting a zero map only if a palette id is absent from the scout result.
  3. Plan: call choose_band_plan with the canonical palette, actual scout maps, color-slot capacity, layer height, and effective_max_layers().
  4. Persist: serialize the selected plan into state.swap_grouping.
  5. Constrain: build band-aware LUTs and run the final solve with the groups and band heights fixed.

effective_max_layers() reserves the minimum white cap while calculating the available color-layer budget. After planning, the runner also computes:

cap_limit_mm = t_max - d_wb - sum(band_layers) × layer_height

That runtime limit participates in the Stage 4 boundary-cap ceiling, keeping the fixed color bands and white cap within the total thickness budget.

How choose_band_plan selects groups

The planner receives the palette in canonical dark-first order and computes ceil(palette size / color slots) groups.

_canonical_partitions enumerates every unlabeled constrained partition exactly once. Filaments retain canonical order within each group, and groups are ordered by the first canonical filament assigned to them. A group is not required to be a contiguous slice of the palette; for example, nonadjacent palette entries may share a band when their measured usage makes that partition cheaper.

For each candidate:

  • the active mask is any pixel with nonzero total color;
  • each group’s required height is the 0.99 quantile of its summed scout thickness over that active mask, rounded up to whole layers and floored at one layer; and
  • the objective is (total raw band layers, predicted white-fill volume, canonical group key).

This prioritizes minimum print height, then minimum fill, with deterministic tie-breaking.

If the winning raw heights exceed the color-layer budget, _clamp_band_layers scales each height down with a one-layer floor. It rejects a budget too small to give every band one layer. The final solve is still authoritative: later band_fill_maps rejects any actual solved color map that exceeds its committed band height instead of silently changing the plan.

The frozen BandPlan retains the groups, selected and unclamped layer counts, usage statistics, quantile, clamp flag, and predicted fill volume.

Fixed-height white fill

Each band must end at one constant Z height so a printer can pause and change filaments across the whole object. band_fill_maps therefore calculates, at every pixel:

white fill = band height - summed color thickness in that band

Negative fill beyond tolerance is a hard error because it means the committed plan is too short for the solved color. Otherwise the fill is clamped at zero.

These per-band white maps are used by prediction/rendering, Stage 4’s band-aware cap request, recipe/Explorer material descriptions, and mesh export. They are internal white structure; they do not create an additional user-selected filament identity.

Persisted swap_grouping

_swap_grouping_metadata writes the JSON-safe swap_banding_v1 block that survives run caching and Saved Run archival. Its main fields are:

FieldMeaning
canonical_palettesolve-owned palette order
groupsone filament-id list per Z band
band_layerscommitted band heights in whole layers
unclamped_band_layerspre-budget diagnostic heights
band_heights_mmcommitted physical heights
pause_z_mmbase top plus cumulative completed band heights, excluding the final band top
layer_height_mm, d_wb_mm, quantilereconstruction constants
scout resolution and per-group useplanning diagnostics
clamped, predicted fill volumeplan diagnostics
cap_limit_mmremaining white-cap budget added after plan selection
banding_costfinal banded-LUT dE cost relative to the scout’s unconstrained LUT

The block is copied into runtime diagnostics and run metadata. A separate swap_plan_availability record can explicitly mark instructions unavailable.

Validation at export

banded_export_plan_from_metadata converts the saved block into a frozen BandedExportPlan. It validates:

  • nonempty, matching groups and layer counts;
  • at least one layer per band;
  • no filament assigned to more than one band;
  • exact palette membership and, when declared, exact canonical-palette agreement;
  • layer height and base thickness agreement with the solved export settings; and
  • declared pause heights against the recomputed band boundaries.

A partial or contradictory plan is a hard export error. For a banded run, materializing the post-solve export bundle also recomputes and stores band-fill maps, replaces the ordinary varying color ceiling with the fixed final band ceiling, and rebases the canonical white-cap upper-surface target onto it.

Slot tables and instructions

Export finalization calls _build_swap_instruction_payload for the selected solve card. The resulting slot plan, instructions, and G-code belong to the completed export response and its published swap_instructions.txt.

Geometry and band boundaries remain solve-owned. AMS capacity is deliberately read from the currently active printer so instructions reflect the hardware the user is about to use. If the current printer has fewer color slots than any solved group requires, instruction generation returns a conflict instead of rewriting the solve.

For a banded run:

  • band_slot_tables assigns each band’s colors to slots 1..N;
  • white slots remain fixed through every transition;
  • generate_swap_instructions renders physical dimensions, Z ranges, every slot table, and the unload/load differences at each boundary; and
  • generate_orcaslicer_pause_gcode emits one M600 per persisted boundary.

The approximate displayed layer number is round(pause_z / layer_height) with a minimum of one. The actual authoritative pause is the physical pause_z_mm value.

If no band plan exists, _build_static_swap_instruction_payload validates that the solved palette still fits the current printer, produces one all-print load table, and returns ; No filament swaps needed.
