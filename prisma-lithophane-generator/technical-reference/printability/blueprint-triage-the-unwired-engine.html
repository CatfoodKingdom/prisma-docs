Blueprint triage: the unwired engine

In one sentence: pipeline.blueprint_triage is an implemented and extensively tested hazard-analysis and repair-planning package, but the live Generator never constructs its analysis context or calls its analyzer, planner, or mutator.

This page describes what the dormant package actually does. It is not a description of current solve-time enforcement or export validation. Those live systems are covered by The live staged printability diagnostic and Robust rectilinear meshing.

Liveness boundary

The production pipeline carries a compatibility slot named PipelineState.blueprint_triage, but it never puts a report there:

BoundaryCurrent behavior
state declarationPipelineState.blueprint_triage starts as None
staged runnerfinalization explicitly assigns None
facade resultcopies that value into SolveResult.blueprint_triage
servernever calls analyze_triage, plan_fixes, or apply_fixes

Repository-wide caller searches find those three public operations only in the package’s test suites and historical development notes. ExposureContext.from_export_bundle is likewise exercised directly only by a test. The code is therefore dormant/test-only, not “computed but unwired.”

The server does import the package’s PrintabilityError, but only for _assert_material_exposure_safe_for_product. That raising helper has no production caller; normal solves use the separate, non-raising material-exposure audit.

Intended package flow

AnalysisContext.from_state requires state.solved_plan; otherwise it raises ValueError. It derives:

  • color-ceiling and final-top maps;
  • a per-pixel material-interval schedule containing base white, ordered color intervals, and a final white-cap interval;
  • per-filament occupancy masks for color and cap material;
  • solve-target luminance/chroma gradient maps and a dE-weighted fidelity prior;
  • triage thresholds derived from the pipeline configuration; and
  • spline forward-model profiles for counterfactual repair scoring.

AnalysisContext, ExposureContext, their nested dataclasses, and their NumPy arrays are mutable. Construction copies the diagnostics mapping but generally retains or derives mutable array objects; this is not an immutable snapshot contract.

Exposure exemptions

ExposureContext can exempt the outer image perimeter and can carry an (H, W, 4) edge mask in up/down/left/right order. from_border_projection marks edges at the projected inner and outer boundaries of a positive-width, positive-height border. from_export_bundle supplies the bundle dimensions and border values to that helper. No product path currently constructs either form for triage.

The seven analyses

analyze_triage runs seven detector families:

AnalysisWhat it reportsVerdict effect
voidsabsent columns or positive-Z gaps between intervalsdisqualifying
floating materialcolumns or intervals unsupported from belowdisqualifying
overlapsinvalid/negative intervals or overlapping adjacent intervalsdisqualifying
sub-featuresper-material, per-layer connected components below area or width thresholdswarning or disqualifying
narrow strandsskeletonized footprints below line-width thresholdswarning or disqualifying
cliffsexposed color-height steps between four-neighbor pixelswarning or disqualifying by depth
skyscrapersisolated, prominent high-side regions derived from cliffsplanning metadata only

The first three walk the interval schedule and enforce structural column invariants. Sub-feature and strand severity use hard printer-width floors and a softer nozzle-derived warning scale. Cliff severity compares maximum exposure depth with one-layer warning and two-layer blocking thresholds. Skyscraper regions do not enter blocking_hazards or warnings; they exist to influence candidate generation and ranking.

Salience comes from Sobel gradients over the solve-grid OKLab target. The package combines luminance and chroma gradients, uses the stored __de__ diagnostic as its residual proxy when present, and folds both into repair ranking.

Report and verdict

The triage PrintabilityReport contains the individual detector outputs, blocking and warning lists, category counts, references to the analyzed plan/context, and a three-value verdict:

It also stores two 16-byte fingerprints. Their coverage is deliberately narrower than the object names suggest:

  • plan_fingerprint hashes only the stack table, segment_stack_id, and cap_height_map. It does not hash segment_id_map, solve pitch, metadata, or every other SolvedMaterialPlan field.
  • exposure_fingerprint hashes only exempt_outer_perimeter and exempt_edge_mask. It does not hash the target image, diagnostics, profiles, thresholds, or other AnalysisContext state.

ValidatedBlueprintToken compares only those two byte strings. It can detect changes covered by those hashes; it is not proof that an arbitrary plan/context pair is globally unchanged.

Repair planning

plan_fixes generates candidates for cliffs, skyscrapers, sub-features, and narrow strands. It does not propose repairs for void, floating, or overlap hazards.

Fix typeGeneratedSimulated for image costApplied
ACCEPTyesnono-op
SHORTENyesyesyes
WALLcliffsyesyes
SMOOTHcliffsyesyes
HYBRIDcliffsyesyes
BULLDOZEskyscrapersyes, as shortenyes, as shorten
TRANSLUCENT_SMOOTH / TRANSLUCENT_HYBRIDnonono

Each candidate receives a cheap score for image, material, shape, workflow, and expected printability gain. The best few viable candidates per hazard are then re-scored with counterfactual_cost, which simulates the local change, runs the spline forward model over affected pixels, and measures the mean positive increase in target-relative dE. A change that improves the modeled match receives zero image penalty.

The optional policy argument controls the top-N counterfactual limit through matching attributes, but the remaining heuristic weights and thresholds continue to come from context.config. It is not a complete replacement policy object.

Applying repairs

apply_fixes mutates the supplied SolvedMaterialPlan in place and returns that same plan. It rejects a batch whose non-ACCEPT target masks overlap. Supported candidates may rewrite segment-to-stack assignments and/or cap heights.

When a state object is supplied, application always clears state.blueprint_triage and state.plan_derived_cache when those attributes exist. If that state also has a non-null config, it then:

  1. rebuilds compatibility thickness maps from the mutated plan;
  2. promotes legacy __de__ and __gamut_mask__ entries from the old thickness-map container into state.diagnostics only when those diagnostics are not already present; and
  3. reassigns state.solved_plan to the mutated plan when that attribute exists.

The shared smooth/hybrid helper grows a cap target with a linear distance falloff. The translucent repair types raise NotImplementedError if supplied manually.

TriageConfig

TriageConfig owns detector thresholds and ranking weights, not the live product’s printability controls. from_pipeline_config derives:

  • hard feature and line-width floors from printability_minimum_extrusion_width_mm, then printer_min_line_width_mm, then 0.40 mm;
  • soft widths from the larger of that hard floor and the nozzle-derived preprocessing feature scale;
  • soft area from the larger squared scale;
  • cliff warning/blocking depths from one and two layer heights; and
  • skyscraper and smoothing thresholds from the hard width and layer height.

These values matter only if an external or test caller constructs the dormant analysis.

Name collisions

There are two unrelated classes named PrintabilityReport:

ClassRoleProduct status
pipeline.blueprint_triage.report.PrintabilityReportinterval hazards, verdict, and proposed repairsdormant
mesh.printability.PrintabilityReportaggregate mesh measurements/classificationhigh-level builder is test-only

There are not two PrintabilityError classes. The only one is defined by pipeline.blueprint_triage.report; the server reuses it in the dormant raising form of the separate material-exposure check.

The live layer diagnostic returns BlueprintPrintabilityDiagnostic, while live mesh export stores plain quality dictionaries and manifest data. Neither is one of these PrintabilityReport classes.
