Assigning images

Assigning images

Properties1
tagscalibration, webapp

Jul 14, 20267 min read

In one sentence: on Images → Assign Images, a three-pane workspace connects the raw lightbox photos you shot outside the app to your samples — you import the photos, register the empty-lightbox blanks that flatfield correction needs, then attach an image (and a matching blank) to each sample so it is ready to extract.

Extraction can’t run until a sample knows two things: which photo is its printed strip, and which photo is the empty-lightbox reference. This screen is where you supply both. A blank is a photograph of the lit lightbox with no strip on it; during extraction the strip photo is divided by the blank to cancel the lightbox’s spatial unevenness — that division is the flatfield correction. See Extraction for how the blank is actually used.

Reach this screen from the Images tab, Assign Images subtab. The three panes read left to right: Registered Blanks, Image Inbox, and Assign Images and Blanks.

The three panes

Image Inbox (center)

This is where raw photos enter the app and where you pick the one to assign.

  • Import from Inbox pulls newly-dropped photos into managed custody. New files land here first; nothing else on this screen can see a photo until it has been imported.
  • Open Inbox Folder opens the exact Calibration/Inbox folder used by this running app, so a user does not have to guess which installation receives a file.
  • Clean Up Unused moves eligible source files to Calibration/Inbox/Removed Images in the packaged Suite, removes their managed copies and custody rows, and leaves assigned sample images or blanks referenced by samples alone.
  • CSV Bulk Assignment opens the bulk-assignment dialog (below).

The grid groups thumbnails into collapsible Unassigned, Assigned, and Ignored sections. Each active thumbnail carries two controls: a rotate button (Rotate thumbnail 90 degrees clockwise), for photos the camera saved sideways, and an ignore button (the ×) that moves a photo you don’t want into the Ignored section. Rotation is persisted as a per-image 90-degree override; the server removes only stale exact cache variants owned by that image (and its registered-blank cache namespace, when applicable), preserving any filename currently expected by another record. The extraction pipeline reads the override for both detection and measurement. Rotation is rejected when the image is tied to a processed, failed, or flagged sample. For rotatable assignments, the server/store clears the sample’s open-side orientation and returns an assigned sample to unassigned, so rotation is an assignment reset for the affected evidence.

Below the grid, Selected Image names the thumbnail you’ve clicked, with two footer actions:

  • ← Register as Blank turns the selected photo into a flatfield reference (it moves to the Registered Blanks pane).
  • Assign Image to Sample → attaches the selected photo to the sample selected in the right pane as its strip image.

Registered Blanks (left)

The catalog of empty-lightbox references. To add one, either select a photo in the inbox and click ← Register as Blank, or drag a thumbnail onto this pane’s drop zone (Drop image to register blank, shown compactly as Drop to Register). Registration assigns an id and records capture time from EXIF when available. SQLite reuses the managed image asset and inserts the registered_blanks relation; only the legacy JSON path copies a second file into blank storage.

Selected Blank names the blank you’ve clicked; Assign Blank to Sample → attaches it to the sample selected in the right pane.

Register one blank per lightbox session and reuse it across every sample shot in that session — the blank only has to match the lighting, not the strip.

Assign Images and Blanks (right)

The sample list, showing what each sample has so far. Selecting a row here sets the target for the two → assign buttons in the other panes; Selected Sample echoes your choice. Each sample’s assigned image and blank appear as slots with an Unassign (×) control to detach either one.

Changing a sample’s image or blank invalidates any earlier processing for that sample — the app clears stale results so the sample re-extracts against the new inputs rather than showing measurements from the old photo.

The assignment loop

For one sample by hand:

  1. Import from Inbox to bring your session’s photos in.
  2. Register the session’s empty-lightbox shot: select it, ← Register as Blank (do this once per session).
  3. Select a sample in the right pane.
  4. Select its strip photo in the inbox, Assign Image to Sample →.
  5. Select the session blank in the left pane, Assign Blank to Sample →.

Repeat 3–5 for each sample. When every intended sample has both an image and a blank, move to Processing and extraction.

CSV Bulk Assignment (the bulk path)

For many samples at once, CSV Bulk Assignment assigns images and blanks from a spreadsheet instead of clicking each one. Place every referenced sample and blank image in the Calibration Inbox first, click Import from Inbox, and then open the bulk dialog. The flow is template → validate → commit.

Download CSV Template gives you a header-only file with four columns:

ColumnWhat goes in it
Sample IDThe sample’s id (exp-123), or just the number 123 when that number is unambiguous.
Sample ImageThe strip photo’s filename (extension optional).
Blank ImageA registered blank’s id, or a photo filename — an unregistered photo here is registered as a blank during commit.
OrientationWhich way the strip’s open side faces: U, D, L, or R (T is accepted as up, B as down).

Choose CSV loads your filled-in file; Validate CSV checks it without changing anything and returns a preview: a per-row table plus counts of rows ready, blocked, blanks to register, and warnings. Extra columns are ignored with a warning. A row is blocked (and skipped) when its sample or image can’t be found, an image is ambiguous, a photo is missing or ignored, an image is already assigned to another sample, or the sample isn’t eligible.

CSV assignment only touches fresh samples: a row is rejected if the sample already has an image, a blank, an orientation, a non-unassigned status, or existing extraction results. This makes bulk import a safe first-fill, not a way to overwrite work you’ve already done.

The commit button reads Import Assignments when every row is clean, or Import Valid Rows when some are blocked (only the ready rows commit). If any ready row names a photo that isn’t a registered blank yet, you’re asked to confirm registering those blanks before the import proceeds. Blank registration and all ready sample assignments then commit as one SQLite transaction: a failure leaves neither partial assignments nor a newly registered-but-unused blank. On success the app reports how many assignments landed and how many blanks it registered.
