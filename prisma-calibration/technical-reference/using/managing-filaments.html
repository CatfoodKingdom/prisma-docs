Managing filaments

Properties1
tagscalibration, webapp

Jul 26, 20266 min read

In one sentence: the Filaments tab is the library of every filament Calibration knows about — you add each one once, giving it a name, manufacturer, material, and color, and set policy metadata that controls white-cap classification, special roles, and model-fit exclusion.

A filament must exist in this library before any sample can reference it. This page covers adding a filament and reading or changing its policy; the layer-by-layer strip that filaments get poured into lives on the Samples and geometries page.

Related: Driving the calibration app · Samples and geometries · The Modeling page · Color Model v1 · Color Model v2 · The Camera Transform

The Filaments table

The Filaments tab is a sortable table, one row per filament, with a summary line above it (e.g. “N filaments, M profiled”). Columns:

  • Filament — the color name, with its color chip.
  • Manufacturer.
  • ID — the slug (see below).
  • Samples — how many samples reference this filament.
  • Processed — how many of those have extracted measurements.
  • Profile — whether a fitted spline profile exists for it.

The toolbar has one button, + New Filament, which opens the create drawer. Clicking any row opens that filament’s view drawer.

Adding a filament

+ New Filament opens a drawer headed New Filament with a Create button. Fill in:

  • Filament — the color name, placeholder e.g. Basic Cyan.
  • Manufacturer — placeholder e.g. Bambu. As you type, previously-used manufacturers autocomplete from the library.
  • Material — placeholder e.g. PLA; defaults to unknown.
  • Hex Color — a color picker swatch and a hex text field, kept in sync. Must be #RRGGBB.
  • The Policy checkboxes and Notes (below).

A Generated ID field previews the slug live as you type the manufacturer and color name. The slug is {manufacturer}-{color_name}, lowercased, with every run of non-alphanumeric characters collapsed to a single hyphen — so “Bambu” + “Basic Cyan” becomes bambu-basic-cyan. If that ID already exists in the library the drawer warns you and blocks the save; manufacturer, color name, and a valid hex are all required. The ID is permanent once created — there is no rename.

The policy checkboxes

Four checkboxes under Policy set how the rest of the system may use this filament. They are the load-bearing part of this screen.

White-cap eligible

Marks the filament as a candidate for the white cap — the diffusing white layer a lithophane is printed against. Calibration snapshots every filament with this flag into the model-white classifier used by the legacy spline and photo-stack fits. A published model library carries the same classifier into Generator, where the configured white base and cap must belong to it. Turn the flag on for white and near-white diffusers; leave it off for colored filaments.

Changing this flag makes affected current legacy-spline and photo-stack fits stale. It does not stale the camera transform, whose corpus does not use the white/color classification.

Special role: Transparent / Special role: Black

Two independent tags that record a filament’s special optical role — a fully clear/transparent filament, or a true black. They are stored on the filament record as descriptive metadata; a filament can carry either, both, or neither. They do not exclude the filament from anything on their own — that is what the exclude flag below does.

Exclude from model fits

The consequential one, and the reason it is styled as a warning. The checkbox itself is labeled Exclude from model fits. When checked, Calibration drops any sample that references the filament from all three production fit families: Color Model v1 (the legacy spline), Color Model v2 (the photo-stack model), and The Camera Transform. Changing the flag also makes affected current fits stale.

There is a related publication effect, but it is not a second live connection between the apps. A model library published after the change records exclude_from_model: true and generation_available: false for that filament. Generator then refuses to use it in new model-backed generation work. An already published library is a static snapshot and does not change when Calibration’s live filament record changes.

Two things are worth being precise about:

  • It drops the sample, not just the swatch. Exclusion is evaluated per sample. A sample is removed from a fit whenever the excluded filament appears in it in any role — whether it is the variable filament being characterized or one of the fixed backing layers underneath. One excluded backing filament therefore quietly removes every sample printed on top of it from the evidence.
  • It is a standing filament policy. This is not a per-run toggle. It is distinct from the per-sample and per-swatch fit controls on The Modeling page, and remains in effect until you uncheck it.

Use it for a filament you have retired, mis-measured, or never intend to print with — it keeps that filament’s data from polluting the models without your having to delete it or hunt down every sample by hand.

Notes and read-only fields

  • Notes — a free-text textarea for anything you want to remember about the filament.
  • Used By N Samples — read-only; lists the samples that reference this filament (click through to open them).
  • ID — read-only; the slug, shown for reference.

Viewing and editing

Clicking a row opens the view drawer: name and chip, manufacturer, material, color (hex and RGB), a Policy summary (White Cap, Special Roles, Model Fit, Generation), notes, the used-by list, and the ID.

Edit (top of the view drawer) switches the same drawer into edit mode, exposing the fields and policy checkboxes with three buttons:

  • Save — commits the changes and returns to the view.
  • Discard — abandons the edits.
  • Delete — removes the filament, but only if nothing depends on it. A filament that is referenced by any sample, has a saved profile, or has processed strip data cannot be deleted; the app tells you so rather than deleting. Retiring such a filament is what Exclude from model fits is for.

Editing lets you change the manufacturer, color name, material, hex, policy flags, and notes. It does not change the ID — the slug is fixed at creation.

Color note: the Hex Color you set here is a display-referred label for the UI, not a measurement. The actual optical behavior of the filament comes from its extracted samples, in a different color domain entirely — see Transmission vs Appearance.
