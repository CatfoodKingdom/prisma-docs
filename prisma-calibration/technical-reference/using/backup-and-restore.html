Backup and restore

Backup and restore

Properties1
tagscalibration, webapp

Jul 14, 20268 min read

In one sentence: the topbar Backup / Restore dialog is where you snapshot the workbook to a ZIP you can move off-machine — a small Essential Data Only database backup or a full All Data and Artifacts package (raw source images optional) — restore either after the app validates and previews it, and separately archive bulky raw camera files out of the active library to reclaim space and pull them back later.

This page covers making backups and restoring them, plus the raw-image archive workflow that lives in the same dialog. It is a manual, operator-initiated screen; the app also keeps its own automatic database snapshots behind the scenes (see Automatic restore points below), which are a different thing and are not managed here.

Related: Driving the calibration app · Running maintenance · Managing filaments

Opening the dialog

The topbar Backup / Restore button opens a single dialog titled Backup / Restore with four stacked panels: Create Backup, Restore From Backup, Archive RAW Images, and Restore Archived Images. Everything below maps to one of those panels.

Backup, restore, and archive all share one lock, so only one of them runs at a time; starting a second while one is live returns a “Backup or restore is already running” error. They are also blocked while a Maintenance job is running (see Running maintenance). Each operation is start-then-report: you kick it off, a progress panel opens, and the dialog refreshes when it finishes.

Create Backup

Under Create Backup, pick a backup type, then click Create Backup. Two choices:

Essential Data Only

A small package of just the Prisma database — the semantic state: filaments, geometries, samples, image assignments, extracted measurements, and model-fit records. It does not include source images, model artifact files, or generated STEP/STL exports. Restoring it replaces only the database and leaves your existing files and exports untouched; those files are not guaranteed to match an independently restored database. Use it for a quick, portable snapshot of the workbook’s knowledge, not as a self-contained model-and-image archive.

All Data and Artifacts

The full working state: the database plus durable managed assets and the geometry STEP/STL exports. It includes the accepted source.jpg/strip.jpg sample visuals and every model artifact referenced by the retained SQLite fits. It deliberately omits regenerable preview-cache JPEGs, interrupted thumbnail transaction files, manual-review images, staged re-extraction candidate sets, generator cache files, logs, and other temporary work. Those are neither restore invariants nor reasons for backup creation to fail.

When All Data and Artifacts is selected, an Include raw image files checkbox appears. Leave it on to fold the camera raw source files (.cr2, .cr3, .dng, and similar) into the ZIP for a truly complete backup. Turn it off to keep everything except those bulky raw originals — the package still carries the database, extracted data, artifacts, and geometry exports, just without the multi-gigabyte source photos. The checkbox only shows for this option; Essential Data Only never contains images.

The backup is written as a timestamped .zip in the app’s backup folder. If Windows temporarily prevents the completed ZIP from being renamed into that folder, Prisma leaves the validated package in the backup .tmp workspace and retries promotion during later startup/activity housekeeping; invalid abandoned temp entries expire after 24 hours. Retrieve completed packages and move them somewhere safe — the dialog is the record that one was made, not a permanent package-management system.

Restore From Backup

Under Restore From Backup, point the Backup File control at a Prisma backup .zip (type or select its path), then click Restore Backup.

A full All Data and Artifacts backup is also the supported way to move an existing Calibration library into a fresh Suite release: create the backup in the old copy, keep the ZIP outside both Prisma folders, start the new blank copy once, and restore the ZIP through this dialog. Do not copy Calibration/Workspace by hand or point two Prisma copies at one working directory. After restore, verify the sample/image counts and Modeling status before retiring the old copy.

Restore never applies a package blind. It first validates and previews the ZIP — checking it is a well-formed Prisma package with an intact database — and shows you a summary of what the package is and exactly what restoring it will replace. Only then does it ask you to type a confirmation phrase (the exact wording depends on the package: an All Data and Artifacts package warns it “will replace all existing data,” an Essential Data Only package warns it “will replace the current database”). The Restore Backup action stays disabled until the typed phrase matches. Before overwriting anything, the app also takes an automatic emergency safety copy of the current database, so a restore is reversible if it goes wrong.

What a restore replaces depends on which package you are restoring:

  • Essential Data Only → replaces the database only; your current images and exports stay as they are.
  • All Data and Artifacts, with raw images → replaces the database, assets, and exports, and brings in the package’s raw images too.
  • All Data and Artifacts, without raw images → replaces the database, assets, and exports, but keeps your current raw source images in place (the package has none to supply).

When the restore finishes, the app refreshes automatically and the restored data is live. Restore refuses to operate when the configured asset tree, STEP export tree, or a contained directory is a symlink/junction/reparse point; it will fail before moving the current library aside. This is a safety boundary against accidentally restoring through a disposable worktree link into another library.

During replacement, Prisma temporarily moves the displaced state into a restore_previous_* rollback directory. It restores that state if validation or the post-restore smoke check fails. After success, cleanup handles Windows read-only files before removing that directory. If some other filesystem problem still prevents removal, the restore remains successful but reports a restore_previous_cleanup_failed warning with the residual path so the disposable copy can be removed manually after verifying the restored library.

Archive RAW Images

Raw camera files are the largest thing in the library and, once extracted, are rarely needed day to day. The Archive RAW Images panel lets you move them out of the active library without losing them. It has two steps, deliberately separated so you never delete originals you have not safely stored first.

Create RAW Image Archive

Create RAW Image Archive packages the current raw source images into a standalone raw-image archive ZIP. It only copies — nothing is deleted or moved out of the active library. Do this first, verify the archive, and move it somewhere safe.

Remove Archived Images From Active Library

This is the destructive step. Point its Archive or Backup File control at the archive you just made (a raw-image archive, or an All Data and Artifacts backup that includes raw images), and the app validates it and previews which active-library source files it covers. Because it deletes local raw files, it is confirmation-gated: you must type the phrase Remove archived images from active library before the Remove Archived Images From Active Library action enables. It only removes files that the archive actually contains, so nothing unmatched is touched. Run this only after the archive is stored somewhere safe.

Restore Archived Images

Restore Archived Images is the inverse: point its Archive or Backup File control at a raw-image archive ZIP (or an all-data backup that includes raw images) and click Restore Archived Images. The app validates the archive, previews how many images are missing from the active library, and restores only the missing compatible source images — it will not overwrite or duplicate images you already have. Use it to pull raw originals back into the library after you archived and removed them.

Automatic restore points (not this dialog)

Separately from anything on this screen, the app keeps its own internal SQLite restore points — automatic, database-only snapshots taken on startup and pruned over time. They carry no raw images, no artifacts, and no ZIP packaging; their sole job is to preserve a recent known-good database for corruption recovery. Applying one first preserves the displaced database under output/restore-points/recovery/; those emergency copies are not selectable restore points and use the same default 12-copy/30-day retention bounds. Restore points are not the same as the user backups you create here and are not managed from this dialog. Treat the Create Backup packages as your real, portable backups; treat restore points as an automatic safety net underneath them. The mechanism behind both lives in Maintenance Operations.
