Processing and extraction

Processing and extraction

Properties1
tagscalibration, webapp

Jul 14, 20268 min read

In one sentence: on Images → Processing Queue you run extraction on every sample that has its photos, rescue the ones automatic detection can’t handle with the Manual Processing corner-picker, then Accept the results that look right — and only an accepted extraction becomes the trusted measurement the models are allowed to learn from.

This page is the operator’s reference for the Processing Queue screen: which button does what, when a sample lands in Failed versus Flagged for Manual Processing, and how the Manual Processing modal recovers a strip the automatic pipeline missed. It does not re-derive how detection, deskew, flatfield, and median extraction work — that mechanism lives in Extraction. Everything here is about driving the queue.

Related: Driving the calibration app · Assigning images · Extraction · The Modeling page

Getting here

Open the Images tab and switch to the Processing Queue subtab (the sibling of Assign Images). A sample only shows up here once it has an assigned photo and blank — assigning those is the previous step, covered in Assigning images.

The screen is split into two panes. The left pane, Pre-Processing Queue, is the work still to be done: samples waiting to be extracted, and the ones that failed or were flagged. The right pane, Post-Processing Review, is the finished extractions waiting for your yes-or-no. Work flows left to right: extract on the left, judge on the right.

The left pane — Pre-Processing Queue

The left pane groups samples into three collapsible sections by their state.

Ready to Process

Samples that have an image and a blank assigned but have not been extracted yet. Each card shows the strip layout, the source photo, the blank, and the open-side arrow, plus per-card actions:

  • Process — extract this one sample now.
  • Flag — mark it for manual handling without extracting first; it moves to Flagged for Manual Processing.
  • Reassign — unassign the photo and send the sample back to Assign Images (used when the wrong photo was attached).

The section’s batch action is Process All (N), where N is the number of ready samples. It runs the full automatic pipeline — strip detection, deskew, flatfield correction, and per-swatch median extraction — across the whole batch, one sample at a time, showing a live progress bar with running counts of processed, flagged, and failed. The underlying mechanism is described in Extraction.

Failed

A sample lands here when a committing automatic run could not finish. In practice that means detection found no strip outline in any of its strategies, or the blank/flatfield image couldn’t be resolved, or something threw partway through. A failed committing run leaves no partial measurements and removes any earlier sidecar; a preview run (commit:false) reports the failure without changing durable sample or sidecar state (Extraction calls the commit path “all or nothing”).

Flagged for Manual Processing

A sample is here because you pressed Flag on it, or because a low-confidence automatic run marked it for review. These samples are not broken measurements — they are ones you’ve decided the automatic path shouldn’t be trusted on.

Cards in Failed and Flagged for Manual Processing carry these actions:

  • Manual Process — open the corner-picker modal for this sample (see below).
  • Unflag — clear the flag; a sample with a usable prior result reverts to processed, otherwise it returns to the ready/assigned state.
  • Reassign — same as above: detach the photo and go back to Assign Images.

Each of these two sections has its own batch action, Manual Process All (N), which opens the modal as a queue that walks the whole section’s samples one after another.

One extraction job runs at a time. Extraction takes a server-side writer lock, so starting Process All (or a manual extract) while another extraction — or a model fit — is already running is refused with a “busy” error rather than queued. This is the same single-job discipline described in Driving the calibration app.

The right pane — Post-Processing Review

Every finished extraction appears here under Processed before it counts for anything. A committed extraction is not automatically trusted — it sits in review with acceptance withheld until you act on it.

Each review card shows the sample, the extracted strip image side by side with a mock strip built from the measured swatch colors, and two actions:

  • Accept — commit this extraction as the sample’s trusted measurement. This is the gate that matters: only accepted extractions feed the models. An accepted sample drops out of the review pane and becomes evidence the Modeling step can include in a fit.
  • Reject — throw the result away and send the sample back to the ready queue for another pass. Rejecting clears the measurements and returns the sample to Ready to Process.

The section header carries the bulk pair Accept All and Reject All, which apply the same action to every card currently in review.

Accepting is reversible in the sense that you can later exclude a sample or an individual swatch from fits on the Modeling tab without deleting it — accept here just means “this measurement is real”; the decision about whether it should train the model is made later.

Manual Processing (the corner-picker)

When automatic detection can’t find the strip — most often with highly translucent filaments that blend into the lightbox — you place the strip’s corners by hand. Manual Process (or Manual Process All) opens the Manual Processing modal, whose header names the sample being worked on.

The modal shows the source photo on a canvas with the instruction:

Click corners of the strip in order: TL, TR, BR, BL.

Click the four corners in that order — top-left, top-right, bottom-right, bottom-left. Placed corners can be dragged to fine-tune them. The controls are:

  • Extract & Process — run the manual pipeline on your four corners and show a preview of the result (the extracted strip). This is a preview only: it does not yet commit anything or change the sample’s state.
  • Reset Corners — clear all four corners and start placing them again.
  • Cancel — abort an in-progress run.

Once the preview appears you get two more buttons:

  • Accept — finalize this manual extraction. It re-runs the extraction to commit the result, marks the sample processed, and clears the flag. In a batch (Manual Process All) Accept advances to the next sample in the queue; on the last sample, or a single-sample run, it closes the modal.
  • Retry — discard the preview and re-place the corners.

The manual path fixes the strip’s direction from your clicked corner order plus the sample’s recorded open-side orientation, so it does not use the brightness heuristic the automatic path relies on. From the flatfield division onward the measurement is identical to the automatic one — the only difference is how the strip was located. See Extraction for the full manual-vs-automatic comparison.

A manually accepted sample lands in the same Post-Processing Review pane as an automatic one — it still has to be part of an accepted measurement to reach the models. (In practice pressing Accept in the manual modal already commits it as processed; it then appears in the review pane for the final acceptance, tying back to the Modeling step.)

The short version

  1. Process All on the left to extract the ready batch.
  2. Anything that lands in Failed or Flagged for Manual Processing → Manual Process, click the four corners, Extract & Process, Accept.
  3. On the right, Accept the good results and Reject the bad ones.
  4. Accepted samples are now trusted measurements — continue to The Modeling page to choose what the fit learns from them.
