The Modeling page

The Modeling page

Properties1
tagscalibration, webapp

Jul 14, 20269 min read

In one sentence: the Modeling tab is where you curate which measurements the color models are allowed to learn from — sidelining a suspect sample or swatch without deleting it — and then press Fit Models to rebuild Calibration’s three current working models (Color Model v1, Color Model v2, and the Camera Transform) from the evidence that is currently included.

This is the last stop before you can publish a complete library for Generator. Everything upstream produced measurements; this page decides which of them count, checks Calibration’s working models for staleness, and triggers the fit. It does not re-explain how each model works — for that, follow the links to Color Model v1, Color Model v2, and The Camera Transform.

Related: Driving the calibration app · Processing and extraction · Managing filaments · Running maintenance · Color Model v1 · Color Model v2 · The Camera Transform

What “evidence” means here

Only accepted extractions are evidence. A sample that has been photographed and processed but whose result you have not accepted in Post-Processing Review does not feed any model — it shows up here under Needs Extraction. Accepting an extraction is done on the Processing Queue; see Processing and extraction. This page assumes that step is behind you and lets you decide which of the accepted measurements the fit should trust.

Two levers coexist, and they are not the same:

  • Per-run curation (this page). The Exclude / Include toggle and the per-swatch controls sideline one measurement for the next fit. Reversible with one click, scoped to a sample or a swatch.
  • Permanent per-filament exclusion. The Exclude from model fits and new generation flag on Managing filaments drops a filament wholesale from every fit and from generation, and stays on until you uncheck it. Use that for a retired or mis-measured filament; use this page for a single bad strip.

The header — model status and Fit Models

The Modeling tab header carries a status line with one chip per working model — Color Model v1, Color Model v2, and Camera Transform — each showing whether that model is current, stale, or missing, and the primary Fit Models button.

  • Current — Calibration’s working model is up to date with the included evidence.
  • Stale — the working model no longer matches its contributing evidence: you have changed included evidence or another relevant fit input since it was built. A Fit Models needed banner appears above the subtabs when anything is stale or missing.
  • Missing — no current working model artifact exists yet.

Fit Models opens the Fit Models workflow (the same job as the Fit Models maintenance operation — see Running maintenance and Maintenance Operations). It runs the unified fit end to end: it rebuilds the legacy spline profiles (Color Model v1), the photo-stack model (Color Model v2), and — when needed — the Camera Transform, all from the currently-included evidence, replacing Calibration’s prior current fit for each family. It does not change Generator. Only one heavy job runs at a time, so if a re-extraction, backup, or another fit is in flight the button reports the conflict rather than starting (see Driving the calibration app).

When all three status chips are current, use the separate topbar Publish Models action to validate and copy that exact generation into an immutable library. Publish to Generator installs it inactive; Export Library Package writes a transferable ZIP. Generator continues using its previously selected library until you explicitly activate the new one through Models → Activate and Restart Prisma.

Three subtabs sit under the header: Overview, Samples, and Filaments.

Overview — is the evidence healthy?

The Overview subtab is a read-at-a-glance summary. Current Evidence is a row of metric cards:

  • Evidence Samples — included samples over total (e.g. 41 / 55), counting only samples with an accepted extraction and at least one included swatch.
  • Swatches — included swatches over total.
  • Excluded Samples — how many samples you have toggled to Exclude.
  • Excluded Swatches — how many individual swatches are currently sidelined.

Needs Attention lists concrete blockers to a good fit: any stale or missing model, and a Samples without accepted extraction count. If nothing is wrong it says No immediate blockers. Treat this list as your pre-fit checklist — clear it (accept the pending extractions, decide the exclusions), then fit.

Samples — curate one strip at a time

The Samples subtab is a table, one row per sample, with columns Sample, Strip, Filaments, Fit State, Extracted Appearance, and Fit Control. Above it are two filters:

  • A Filter dropdown: All, Included, Excluded, Has Excluded Swatches, Needs Extraction, Stale, Missing Model. (Stale and Missing Model only return rows when a model actually is stale or missing.)
  • A filament filter: Filaments… opens a Filter Samples by Filament picker; selected filaments show as chips, and Clear removes them. Use it to see every sample that a given filament appears in.

Including and excluding a sample

The Fit Control column holds one button per row: Exclude when the sample is currently included, Include when it is excluded. Clicking it flips that sample’s participation in the next fit. Excluding keeps the measurement intact — it is still in the workbook, still viewable — it is simply withheld from the fit. Excluding (or re-including) a sample marks the affected models stale; that is expected, and the fix is to re-run Fit Models.

The comparison drawer

Clicking anywhere on a row (outside the button) opens a read-only comparison drawer for that sample. It shows, per swatch, the measured colors beside each model’s prediction — Measured Colors, Predicted Colors (Color Model V2), and Predicted Colors (Color Model V1) — under a Color Comparison module. Two display toggles control what you see, they do not change any data:

  • An Appearance / Transmission toggle picks the domain the strips are drawn in (what the camera sees versus raw transmission — see Transmission vs Appearance).
  • A Color Corrections toggle switches the predictions between with- and without-corrections, so you can judge how much the corrections are doing (v1’s pair corrections and v2’s correction layer — Color Model v1, Color Model v2).

Use this drawer to decide whether a sample is trustworthy before you exclude it: if the model already tracks the measurement well, leave it in; if one swatch is wildly off, sideline that swatch.

Per-swatch exclusion

Excluding a single swatch rather than the whole sample is done on the sample’s own record, in its Model Fit controls (the Included / Excluded toggle per swatch, alongside the Exclude this sample from model fits checkbox) — reached by opening the sample from the Logbook, not from this comparison drawer. Swatches you sideline there show up here as the Fit State “N swatches excluded” pill and under the Has Excluded Swatches filter. See Processing and extraction for that surface.

Filaments — is each filament well covered?

The Filaments subtab answers a different question: does every filament have enough included evidence to be modeled well? It is a coverage table with columns Filament, Brand, Samples Containing It, Included Samples, Included Swatches, Excluded Swatches, Thickness Coverage, Role Coverage, and Health. Health is a colored pill summarizing the row:

  • Good — enough included swatch evidence.
  • Sparse — limited included evidence (few swatches); the fit for this filament is thin.
  • Excluded only — the filament appears in samples, but every one of them is excluded, so it contributes nothing.
  • Excluded — the filament carries the permanent Exclude from model fits and new generation flag from Managing filaments.
  • Stale — a model needs refitting.

Clicking a row opens the filament’s coverage detail: a Summary (health state and whether it is included in fits), a compact Coverage block (included/excluded sample and swatch counts), a Model State panel, and an Evidence Samples list of every sample containing the filament. Show In Samples jumps to the Samples subtab pre-filtered to this filament, so you can act on the thin cases directly.

Read this tab as a gap-finder: a Sparse or Excluded only filament is a signal to print and calibrate more strips for it, or to re-include a sample you sidelined too aggressively.

The usual loop

  1. Overview — clear Needs Attention (accept pending extractions upstream, resolve stale/missing).
  2. Samples — spot-check suspect rows in the comparison drawer, Exclude the bad ones.
  3. Filaments — check for Sparse / Excluded only coverage; re-include or plan more strips.
  4. Fit Models — rebuild Calibration’s three working models from the included evidence; the chips return to current.
  5. Publish Models — copy the exact current set into a new immutable library, then activate it from Generator’s Models menu when ready.
