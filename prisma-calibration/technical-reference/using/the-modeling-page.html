The Modeling page

The Modeling page

Properties1
tagscalibration, webapp

Jul 15, 20269 min read

In one sentence: the Modeling tab is where you inspect and curate the accepted measurements available to model fitting, compare the two color models with measured swatches, and run Fit Models — which always attempts Color Model v1 and v2, replaces each successful stage, and rebuilds the Camera Transform only when its preflight says that is necessary.

This is the last stop before you can publish a complete library for Generator. Everything upstream produced measurements; this page decides which of them count, checks Calibration’s working models for staleness, and triggers the fit. It does not re-explain how each model works — for that, follow the links to Color Model v1, Color Model v2, and The Camera Transform.

Related: Driving the calibration app · Processing and extraction · Managing filaments · Running maintenance · Color Model v1 · Color Model v2 · The Camera Transform

What “evidence” means here

Only accepted extractions appear in the Modeling sample and filament evidence tables. A sample whose processing result has not been accepted is counted under Samples without accepted extraction on Overview, but it is not a row in the Samples subtab. Accepting an extraction is done on the Processing Queue; see Processing and extraction.

Two levers coexist, and they are not the same:

  • Sample and swatch curation. The sample and swatch controls sideline one accepted strip or individual swatch from subsequent fits without deleting its measurement. The state persists until you include it again. These controls are available directly in the Modeling sample drawer and on the sample record in Logbook.
  • Persistent per-filament exclusion. The Exclude from model fits flag drops a filament wholesale from model fitting. A library published afterward records it as unavailable for new Generator work; an older published library remains unchanged. You can change the flag from Managing filaments or the filament detail drawer on this page. Use it for a retired or invalid filament; use sample/swatch exclusion for isolated suspect evidence.

The header — model status and Fit Models

The Modeling tab header carries one status entry per working model — Color Model v1, Color Model v2, and Camera Transform — plus the primary Fit Models button.

  • Current — Calibration has a registered fit row whose currentness_state is current; no tracked mutation has marked that row stale.
  • Stale — a tracked mutation to contributing evidence or another fit input has invalidated the registered working fit. A Fit Models needed banner appears above the subtabs when anything is stale or missing.
  • Missing — Calibration has no registered fit row for that model family.

These entries report registered currentness; they do not re-hash the model files. Publish Models performs the stricter artifact, pointer, and filament-catalog validation before it allows a library to be created.

Fit Models opens the same noncancelable maintenance workflow documented under Running maintenance and Maintenance Operations. Its preflight always schedules the legacy spline profiles (Color Model v1) and Photo Stack model (Color Model v2). The Camera Transform is scheduled only if it is forced or its registered inputs/artifacts are missing, invalid, or changed; it is skipped when current and can also be skipped when fewer than five eligible samples exist. Each published family replaces Calibration’s prior current fit, but the three-family workflow is not one all-or-nothing transaction. V1 can also publish its successful filament subset and then cause the overall workflow to fail and stop when another filament failed. It does not change Generator. Only one conflicting heavy job runs at a time, so a conflict is reported instead of starting another fit (see Driving the calibration app and Model workflow, publication, and review).

The internal publishers compensate for ordinary exceptions, but their filesystem/pointer and SQLite steps are not protected by a process-kill journal. Do not kill Calibration while model publication is in progress. After an abnormal stop, status may still reflect the registered database row while a pointer or live v1 file changed; use publication readiness as the stricter integrity check before publishing a library.

When all three status entries are current, use the separate topbar Publish Models action to validate and copy that exact set into an immutable library. Current status is necessary but not sufficient: publication can still be blocked by a missing, changed, or invalid registered artifact or by invalid public filament data. Publish to Generator installs a successful library inactive; Export Library Package writes a transferable ZIP. Generator continues using its previously selected library until you open Model Library → Manage, select the new library, and choose Activate and Restart Prisma.

Three subtabs sit under the header: Overview, Samples, and Filaments.

Overview — is the evidence healthy?

The Overview subtab is a read-at-a-glance summary. Current Evidence is a compact table:

  • Evidence Samples — model-eligible samples over all accepted-extraction samples (for example, 41 / 55). Eligibility requires that the sample itself is included, none of its filaments is persistently excluded, and at least one swatch remains included.
  • Swatches — swatches in model-eligible samples over all swatches in accepted-extraction samples.
  • Excluded Samples — how many samples you have toggled to Exclude.
  • Excluded Swatches — how many individual swatches are currently sidelined.

Needs Attention lists stale and missing models, samples blocked because one of their filaments is excluded, and samples without an accepted extraction. If none of those conditions applies it says No immediate blockers. This is a status summary, not a guarantee that every included measurement is high quality; the sample comparisons remain the place to judge that.

Samples — curate one strip at a time

The Samples subtab lists accepted-extraction samples with columns Sample, Strip, Filaments, Fit State, and Extracted Appearance. The Sample, Filaments, and Fit State headers are sortable. Above the table are two filters:

  • A Filter dropdown: All, Included, Excluded, Filament Excluded, Has Excluded Swatches, Stale, and Missing Model. The last two show all otherwise-matching accepted samples only while at least one model has that state; otherwise they are empty.
  • A filament filter: Filaments… opens a Filter Samples by Filament picker; selected filaments show as chips, and Clear removes them. Use it to see every sample that a given filament appears in.

Including and excluding a sample

Click a row to open its review drawer. The Sample Exclusion module contains Exclude Sample or Include Sample; exclusion requires a second confirming click. Excluding keeps the measurement intact but withholds the entire sample from later fits. Changing this state can mark models that used the sample stale; re-run Fit Models when you are satisfied with the evidence selection.

The comparison drawer

The drawer shows Transmission Domain and Appearance Domain side by side; there is no domain selector. Each domain aligns the extracted strip or strip diagram with Measured, Predicted (Color Model V2), Predicted (Color Model V1), and a per-swatch Prediction Error graph. The graph is Euclidean OKLab distance, with a fixed display scale and reference landmarks; it is a comparison aid, not a fit-quality acceptance gate.

The Color Corrections: On/Off toggle switches both models between their corrected and uncorrected predictions. That display preference is kept in browser session storage and does not mutate a fit. Measured appearance comes from the accepted extraction. Model predictions originate in linear transmission; their appearance rows require the current Camera Transform, so appearance predictions report unavailable if that transform cannot be loaded. See Transmission vs Appearance, Color Model v1, and Color Model v2.

Per-swatch exclusion

The drawer’s Swatch Exclusion module is a strip-shaped grid. Each variable-layer cell shows its nominal thickness and whether it is included; excluding a swatch requires confirmation, while including it is immediate. These are the same persistent fit controls exposed on the sample’s Logbook record. A partly excluded sample receives an N swatches excluded Fit State pill and appears under Has Excluded Swatches. A sample containing any permanently excluded filament is marked Filament Excluded and is ineligible regardless of its own sample/swatch controls.

Filaments — is each filament well covered?

The Filaments subtab answers a different question: does every filament have enough eligible evidence to be modeled? It is a sortable coverage table with columns Filament, Brand, Samples, Fit Samples, Incl. Swatches, Excl. Swatches, and Health. Health is a colored pill with this precedence:

  • Good — at least eight included swatches, provided none of the higher-priority states applies.
  • Sparse — fewer than eight included swatches.
  • Excluded only — the filament appears in accepted samples, but none of those samples is currently model-eligible.
  • Excluded — the filament carries the standing Exclude from model fits flag from Managing filaments.
  • Stale — one or more registered models is stale; this takes precedence over Sparse and Excluded only, but not the filament’s own Excluded state.

Clicking a row opens the filament detail drawer: Summary contains the persistent Exclude from Fits / Include in Fits action, Coverage reports included/total sample and swatch counts, Model State repeats the three registered-model states, and Samples lists every accepted sample containing the filament. Excluding a filament requires confirmation. Show In Samples jumps to the Samples subtab pre-filtered to this filament.

Read this tab as a gap-finder: a Sparse or Excluded only filament is a signal to print and calibrate more strips for it, or to re-include a sample you sidelined too aggressively.

The usual loop

  1. Overview — clear Needs Attention (accept pending extractions upstream, resolve stale/missing).
  2. Samples — spot-check suspect rows in the comparison drawer, Exclude the bad ones.
  3. Filaments — check for Sparse / Excluded only coverage; re-include or plan more strips.
  4. Fit Models — replace Color Model v1 and v2, and replace the Camera Transform when its preflight schedules it.
  5. Publish Models — after all three are current, copy the exact current set into a new immutable library; activate it later through Generator’s Model Library → Manage control.
